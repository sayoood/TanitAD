# bars8 EP-clause stratum fix (2026-10-21) -- the stratum read an ARM-DEPENDENT quantity as if it were model-independent

**Defect.** `navsim_bars8.load_run` built the EP-clause stratum ("best compliant progress <= 5 m") from the bar arm's scorer-hook
`max_compliant_progress_m` and asserted it was identical across arms (`ep_clause_source_consistent`). On the refcv8 EMA-48,852 navtest
read that control read **MISMATCH at 466.96 m** -- correctly: the hook is the devkit's max over ALL proposals, **including the agent's
own**, so it differs per arm. The control caught a defect in the stratum, not in the scorer.

**MEASURED 2026-10-21 on the navtest read (7 arms x 12,146 rows: R8_LEGAL, _s1, R8_RT, _s1, R8_PRIV, PRIOR_ha0p, STOP):**

| quantity | value |
|---|---|
| hook == max(progress_raw_m x multiplier_prod) over the 2 proposals | exact (max abs diff 0.0) |
| PDM reference proposal (index 0) product, cross-arm max abs diff | 9.8e-10 m (model-independent) |
| tokens where the agent raised the max | 2,446-2,599 per model arm; 606 for STOP |
| EP-clause fired on the STOP rows: hook / reference | 1,006 / **1,296** (10.67 % of 12,146) |

**Fix.** `oracle_compliant_progress_m(row)` = the PDM reference proposal's progress x multiplier product (index 0; NavSim v1 scores
[PDM-Closed reference, agent]); `ep_clause_mcp()` builds the stratum from it and emits two controls: `ep_clause_source_consistent`
(the reference value agrees across every arm and the STOP rows, < 1e-6 m) and `mcp_hook_identity` (every row's hook equals the devkit's
max over its proposals, < 1e-9 m; `agent_raised_max` per arm reported beside). A row without the [reference, agent] pair is REFUSED.

**Tests.** Three new literal tests in `tests/test_navsim_bars8.py` (analytic rows: reference 4 m, agent 9 m, the stratum must read 4 m)
and a deliberate-regression arm `ep_clause_agent_inclusive` in `tests/test_mutation_bars8.py` that restores the old definition and must
turn `test_ep_clause_oracle_is_the_reference_proposal_literal` RED (it does). The full-split control keeps the old STOP-hook count 1,006
as a literal and now asserts the reference count 1,296. Green record: `raw/pytest_bars8/epfix_2026-10-21.green.txt`.

**What it changes.** Only the EP-clause STRATUM (a beside-row) and its control; no bar (N1..N4) reads the stratum. The banked
`NAVSIM_BARS_step48852_ema.json` carries `[CONTROL MISMATCH: ep_clause_source_consistent]` in its label; the re-run with this fix (and the
N2/N3 summaries) supersedes it.
