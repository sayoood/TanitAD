5. RESUME / STOP / FAILURE
   Resume = launch the same command again.  A finished step is skipped only if its done record names THIS checkpoint (three times), THIS tool digest and THIS command, and its outputs are all there; an incomplete earlier attempt is MOVED to
   <OUT>\_incomplete_*, never deleted; chain.out of the previous start is rotated to chain.out.prev_*, so the waker never sees an old marker.
   Stop it: create logs\STOP (the chain exits before its next step; a running step finishes and is recorded).  Two instances cannot run (logs\chain.lock + the owner's winpid).
   After a ZZSOUP-STOP the message names the cause.  Typical: a step failed (rc), a tool or checkpoint changed under it, a guard stayed LOW for 2 h, a PINS difference.  Fix the cause, launch again.
   ZZSOUP-DONE ... reader rc 0 = an outcome row written | 2 = REFUSED (a control failed; nothing written: read logs\soup_read.out for which) | 3 = UNPLACED (written) | anything else = the reader crashed.
   A REFUSED read is not a result.  Fix what the failed control names and re-read; the steps are NOT re-run (their done records stand).
