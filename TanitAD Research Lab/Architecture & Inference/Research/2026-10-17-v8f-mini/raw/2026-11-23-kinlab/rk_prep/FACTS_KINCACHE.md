Header fields compared field by field: the seven of the brief (`label_kind`, `bank_json_sha256` = `bank.sha256`, `labeller_sha256` = bytes of `DR.__file__`, `dagger_sha256` = bytes of `DG.__file__`, `n_records`, `eligible_index_sha256` = sha256 of `bank._ok_idx` int64 bytes, `clip_store_sha256`) **plus two I added that only make it stricter: `records_sha256`** (reason, r, tick, join-mapped ci, `p10f[:, -1, :3]`; so a planted or edited record set with the same bank.json sha is refused too) **and `arrays_sha256`** (the cache's own arrays; a flipped byte is refused). `clip_store_sha256` = sha256 over (join index, clip name, full `pose` [T,4] float64 incl. the speed column) of every clip an ok record uses, ascending join index. Stored: `slot`, `label`, `is_kin` (kin_v1 only), `status_counts` and `census` as JSON bytes, `n_labelled` in the header.
Consequence for ops: `dagger_sha256` binds the cache to the bytes of `v8f_dagger.py`, so **build the cache from the final landed commit**; any later edit of `v8f_dagger.py` or `v8f_recovery.py` makes the cache refuse (named) and it must be rebuilt.

## Precompute (no new script)
The trainer's own `--selfcheck-only` with the flag and an absent PATH computes the labels and writes PATH (tested: `test_selfcheck_only_with_an_absent_path_is_the_precompute...`; the directory is created). CPU time: **kin_v1 2.2 s per 4,000 ok records here = 0.55 ms/record; speed_v1 0.22 s**. Extrapolated to a full bank (1.49 M ok records, ESTIMATED): kin_v1 about 14 min on this box (the pod measured 27 min niced and shared), speed_v1 about 1.4 min. Not run at full size. File size 1.89 MB per 4,000 ok records (0.47 kB/record), so about **0.7 GB per full bank** (ESTIMATED). A hit costs: the file sha256 + the arrays hash + the record hash + one `get_kin` read of every used clip (4,500 records: identity 4 ms, read 6 ms; at full size dominated by hashing 0.7 GB, seconds, ESTIMATED).
