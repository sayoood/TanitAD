## 2. The deciding statistic (IA-0 skill against Copy-Last, by IMAG1B's two-part rule)
* Copy-Last prediction of the state at j + k = the state at j. Skill = sum(e_copy - e_pred) / sum(e_copy), e = squared L2 distance to the encoded future in the level's own latent; 0 = Copy-Last, 1 = perfect. Episode-moment form = IMAG1B's `Mom` (the same class), so the bootstrap is IMAG1B's: episode-cluster, B = 2,000, seed 0, paired (every row of every arm shares the same 141-episode draws).
* **Reference (the only reading of "IMAG1B's rule" at these horizons)**: IMAG1B's rule is "bootstrap 95 % interval excludes the null on the claimed side AND the point is beyond the 97.5th (above) / 2.5th (below) percentile of the statistic's own permutation distribution over R = 199 draws". IA-0 in IMAG1B has no probe, and its reference is the derangement of the ANSWER. Applied here: in each draw the encoded future of every anchor is replaced by the encoded future of another anchor of the same clip (a derangement, IMAG1B's `mrr_mom` construction), and BOTH terms (Copy-Last and predicted) are recomputed against that answer. This is what keeps a prediction that merely differs from the present along a fixed direction from reading as skill (the IMAG1 failure). Seeds `[level, k, draw]`. The paired sign-flip reference is not used.
* Separated above = `lo > 0` and point above the 97.5th percentile; below = `hi < 0` and point below the 2.5th.
* **IA-0 health** = IMAG1B's: MRR of the encoded future among the clip's anchors with the predicted latent (k = 1) as the query, against exact chance, same two-part rule with the derangement reference (R = 199; `mrr_mom` imported from IMAG1B), plus RankMe of predicted and Oracle latents. HEALTHY at a level iff separated at the arm's seed.
* Per run: a level BEATS iff skill at its band end (L1 2.0 s, L2 6.0 s, L3 12.0 s) is separated above 0. Per arm, both seeds required: a level counts for the arm only if it beats at every seed present.
* Outcome per arm: BAND-MET = all three beat and all three HEALTHY; BAND-MISS = none beats; BAND-PARTIAL = otherwise, naming the levels that beat. One case the card does not name (all three beat, health fails somewhere) is printed as BAND-PARTIAL with the health failure stated beside it. Per-seed outcomes are printed too.
* A difference between arms is a lever effect only if it exceeds the R35b floor = the absolute difference of R35 s0 and R35b s0 skill at that level's band end (the floor row prints "R35b pending" until R35b_s0 is read).

## 5. Controls (the read is INVALID if one fails) and their tolerances, stated before they were run
1. **M2b reproduction through this code path** (`control_m2b.py`): the two M2b models (`v8f-mini-hacc/M2b_s{0,1}_hacc.pt`) on IMAG1B's own eval-141 windows (`wmact/latents.pt`, 1,976 windows, 141 clips), the same `encode`, then THIS code's `roll_cells` (context 1) and `health_stats`. Expected = `imag1b/RESULT_IMAG1B.json` ia0 of eval141. Tolerances: MRR within 1e-3 absolute (six values: L1..L3 x s0, s1), chance within 1e-9, RankMe (predicted k = 1 and Oracle k = 1) within 1e-3 relative.
2. **Copy-Last against itself reads exactly 0.0** (point, lo, hi, every level and k of every arm), checked in every arm.
3. **Built equals argv** for every run: strides (three BUILT readers), trained k (free-run predictor calls), free-run anchor count, context built, history K, history dilation, causal pad; a mismatch raises `LadderMismatch` and the arm is not read. The frozen adapter hash of every arm equals the cached frames' hash.
4. **Deliberate regressions that must turn a check RED** (`test_ladder_read.py`): the wrong stride in the argv; a Copy-Last reference shifted by one step; the wrong seed's latents against the M2b expectation; a planted fixed-direction shift that must not read as skill; a reach that is off the grid reported as on the grid.
