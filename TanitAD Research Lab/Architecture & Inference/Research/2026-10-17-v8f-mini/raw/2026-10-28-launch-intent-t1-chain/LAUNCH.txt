4. RESUME / STOP
   Resume = launch the same command again.  A finished step is skipped only if its done record names THIS checkpoint, THIS tool digest and THIS command; an incomplete earlier attempt is moved to <OUT>\_incomplete_*, never deleted.  chain.out of the previous start is rotated to chain.out.prev_* so the waker never sees an old marker.
   Stop it: create logs\STOP (the chain exits at its next check) -- never kill a rollout midway unless you accept the move-aside on resume.  Two instances cannot run (logs\chain.lock + the owner's winpid).
   After a ZZLIT1-STOP: the message names the cause.  Typical: a pull WRONG (the run record or K-SHARE re-verified from the pulled files disagrees with the log -- waiting cannot fix it; the run is not read), the box-2 chain STOPPED or failed a control, a guard LOW for 2 h, a pinned file or the tool tree changed, tokens that disagree on commit / reader / PREREG.  Fix the cause, relaunch.

5. WHAT IT DOES NOT DO
   No training, no GPU, no box-2 contact (it only READS the pulls box 2 puts on E: and the chain log), no git write, no deletion.  The reader decides every verdict; the chain only produces the rollouts, the manifest and the reader call.
