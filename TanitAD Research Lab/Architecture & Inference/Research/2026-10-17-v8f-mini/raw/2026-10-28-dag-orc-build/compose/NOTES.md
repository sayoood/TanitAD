## The semantics, as built
* Flag off (default): the loop runs its two ORIGINAL lines, `ego.apply` then `dag.apply` (`v8f_mini_train.py:1803-1804`, text unchanged, one indent deeper). Nothing new is called, no new RNG is drawn.
* Flag on: `EgoDaggerCompose.apply` (`:519-529`) draws the swap first (`self.dag.apply`), then the perturbation at its own p from its own seeded generator, with `exclude=<the swap's mask>`; the overlap is
  MEASURED from the two selection masks after both applies and a nonzero count raises `ZZEGO-DAGGER-OVERLAPZZ`.
* `EgoPerturb.apply(.., exclude=None)` (`v8f_mini_data.py:683-706`): the mask removes samples from the ELIGIBLE set (`eligible_free`, `:670`) before the selection. The draws are untouched by it (each sample's
  selection / scale / drop / yaw values are what they are without the mask), so the ego share over the non-swapped eligible is p. `n_eligible` counts the non-excluded eligible samples ("non-swapped eligible").
  `exclude=None` is the old path, line for line.

## The run record (field names are an interface)
Kept as they were: `dagger_n`, `dagger_eligible`, `ego_perturb_n`, `ego_perturb_eligible` (and `*_rows`, `*_nav_kept`). Added exactly as named: `ego_dagger_overlap_n`, `ego_perturb_with_dagger`.
**One deliberate scoping:** in `summary.json` TOP LEVEL the two new keys exist only for a composed run. A flag-off summary keeps its pre-change key set, because the saved-reference test of the full repo
(`test_v8f_dagger_train.py::test_defaults_reproduce_the_pre_dagger_trainer_bit_for_bit`, skipped when `raw/2026-10-26-dagger-train/*.ref` is absent) asserts that set. A reader must therefore use
`summary.get("ego_dagger_overlap_n", 0)` / `summary.get("ego_perturb_with_dagger", False)`, or read `summary["levers"]["ego_perturb_with_dagger"]` / `["ego_dagger_overlap_n"]`, which are present for EVERY run
(False / 0 when off; banked CTRL runs predate the change and carry neither anywhere).
The meaning of `ego_perturb_eligible` changes with the flag (it counts the NON-swapped eligible samples when composed), as AMEND1 requires.

## Launch gate
`G-DVB`: the flag has its entry and its read-back (`bad_ego_dagger`). `G-LIVE`: `ego_dagger_compose_probe` (a composed arm that fails it is refused with `ZZDVB-REFUSEDZZ ego-dagger-compose: ..`, nothing written).
The probe uses swap p = 0.5 and perturbation p = 1.0 at the first probe step k in -1..-64 that shows both levers on the real probe batch; if no step does, the gate REFUSES (the composition cannot be seen).
Not done (not asked, not in this tree): `stack/scripts/launch_gate.py`'s per-profile argv rules and the box-2 chain's pre-flight greps do not know the flag; a chain that launches the A arm must name `--ego-perturb-with-dagger`
and its pre-flight should grep the tip for `ego_perturb_with_dagger` / `EgoDaggerCompose` (the way the ORC chain greps `b = ego.apply(b, step)`; that text is still present, once).

## One defect found by the existing suites, and fixed
The first full run of `test_v8f_ego_perturb.py` (78 passed, 2 failed) caught my own change: `ego_perturb_probe` passed `exclude=` to `ego.apply` unconditionally, and two existing tests replace `EgoPerturb.apply`
with a wrapper that has no `exclude` parameter (`TypeError ... unexpected keyword argument 'exclude'`). Fixed: the probe now passes `exclude` only when given (`xk`, `v8f_mini_train.py:1027-1030`), so the flag-off probe calls
`ego.apply` exactly as before. Every suite was re-run after the fix.
