## R2. H-CRAWL-02 ambiguities fixed
1. **How speed reaches the planner at tick 0 (read from source).** `forward_infer` (`v8f_mini.py:773`) -> `_forward` (:726). At tick 0 the ages are (0, 0) so S, T and O all read the NOW row only: `_at(p10f, last)` = (v, a, kappa, v^2, v a, v kappa, v^2 kappa, a kappa) (:675, :686, :702), the P10 prior `prior(p10f[NOW], base)` (:710) with `base` = kd_x extrapolation of (v0, a0, kappa0), and `limit` = the 4 s max-speed bucket (:676). Older `p10f` rows are not read at tick 0 (control: scrambling them changes the output by exactly 0.0). "Speed history" therefore reaches the planner only as: the one-frame backward difference `a`, the v-dependence of `kappa = omega/max(v,2)`, the products, `base`, and the `limit` bucket.
2. **Counterfactual implementation (the closest faithful version).** Operate on the window's native-track speed column (rows <= 2 t0) and the cache speed `v` (rows <= t0), then rebuild every derived input with the tool's own functions (`yaw_kin_from_track`, `kin_features`, `kdx_base`, `ego_channels_native`, `causal_bucket`) and let the tool's `build_item` do the rest. Positions, yaw and the camera are untouched, so a speed shift is a speed-SENSOR counterfactual (odometry no longer agrees with it). Measurement tool only, never deployed.
   * shift: `v' = max(v + delta, 0)` on every row <= t0; delta in {-0.5, +0.5, +1.0} m/s. Negative speeds are outside the data's support, hence the clip; so `delta_in` is the REALISED change of the current speed `v0' - v0`.
   * history-zero: the speed column is replaced by its current value `v0` on every row <= t0 (`a0 = 0`, the bucket from `v0` alone), `omega` and positions kept.
   * v_in = 0 (positive control): the speed column is set to 0 on every row <= t0.
   * image swap: `feats` and `frame_ok` replaced by those of a DONOR window at tick 0, speed history unchanged. Primary donor = a launch window of a different episode (fixed deterministic derangement); secondary donor = a GT-stay window of a different episode. The card gives no threshold for "barely changes"; reported descriptively.
3. **Output speed** (from the tick-0 plan `traj30`, 30 knots at steps 1..30, no rollout): primary `v_out = |plan[10]-plan[8]|/0.4` = the speed at knot K[10] = exactly what `v_own` at tick 1 is made from (`mlaunch.own_state_speed_cf`). Secondary: the same at index 20 (4 s) and the final chord `|plan[29]-plan[28]|/0.2` (the 6 s speed of the launch label). Also reported: the same S_v for the P10 prior alone (`out["p10"]`, upsampled) and for the residual (plan - prior), as attribution, not as a card quantity.
4. **S_v** = `sum_i dv_out,i / sum_i dv_in,i` (ratio of sums over a window subset; equals mean(dv_out)/delta when nothing is clipped). Per delta, and pooled over the three deltas (`sum over delta and i` in both parts). CI: episode-cluster bootstrap of the ratio (windows resampled by episode, the ratio recomputed, via `taniteval.ci` with an index-valued reducer). Run difference S_v(DAG-OACC) - S_v(REP): `paired_episode_cluster_bootstrap` on index-encoded values (same resampled episodes).
5. **Subsets.** PRIMARY = stopped-start launch windows (`v0 < 0.5`, the card: "S_v in [0.6,1.0] on stopped-start windows"); SECONDARY = all 327; THIRD = moving launch windows (`v0 >= 0.5`). The primary subset size is reported; fewer than 10 episodes in it is labelled under-powered.
6. **Committed verdict rule for H-CRAWL-02** (pooled S_v, primary subset, h = 10, both runs):
   * card falsifier 1 fires iff on BOTH runs `S_v <= 0.3` and the CI upper bound `< 0.5` => output speed largely independent of input speed; 04 and 05 lose their mechanism.
   * hypothesis "supported" iff the point `S_v >= 0.6` on both runs (the CI lower bound vs 0.6 is stated).
   * anything else: "between the committed outcomes", region stated.
   * card falsifier 2: "equal across the two runs" is read as the paired CI of S_v(DAG-OACC) - S_v(REP) CONTAINING 0 (the weak, constant-free reading; whether the CI also lies inside +/-0.15 is reported). If equal while the launch gaps differ by 0.556, the run-to-run difference is not shortcut strength. If separated, the card's "tracks" is read by sign: the run with the worse launch gap (REP) must have the larger S_v.
7. **Controls (rows void if one fails):** delta = 0 through the rebuild path equals the untouched tool path with max |diff| exactly 0.0 on the batch tensors and on the plan (if the rebuild is not bit-identical, every dv is taken against rebuild(delta=0), the failure and its size are reported and it is a failed control); positive control v_in = 0 must lower mean `v_out` on the moving windows with a CI excluding 0; the tick-0 plan from my forward call must reproduce the stored `plan[:,0]` of the ticks file (reported max abs); older-p10f-rows scramble = exactly 0.0; image-swap with the window's own image = exactly 0.0.
