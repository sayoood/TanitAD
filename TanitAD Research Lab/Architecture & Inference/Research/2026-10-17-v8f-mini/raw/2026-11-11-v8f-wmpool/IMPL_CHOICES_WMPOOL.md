## 1. Choices
* **Flag:** `--wm-pool {mean,att25}`, default `mean`. Config field `V8FMiniConfig.wm_pool` (default `"mean"`). `mean` builds R35H bit for bit (no module, no state-dict key, no batch key). `att25` = P-ATT.
* **Cell layout (token index -> grid position):** the adapter output is `[F, 40, 256]` = the `pool4x10` grid (`n_tok = 40`, `v8f_mini.py:322-326` in the EGOWM tree, `V8FMiniConfig.n_tok`; `--grid pool4x10` -> `n_tok=40`, trainer line 407). Token `i = r*10 + c`, `r` in 0..3 (4 rows), `c` in 0..9 (10 columns), row-major. PRIMARY for the convention: the programme's own 2 x 5 reader `v8f_mini_eval_speedread.py:120-132` (`scene_raw`, `POOL_TO`) does `x.reshape(B, ph, gh//ph, pw, gw//pw, d).mean((2,4))` on the `(4, 10)` grid. The cell is `x.reshape(F, 2, 2, 5, 2, d).mean((1, 3))` giving `[F, 2, 5, d]`, flattened to 10 cells, **cell `k = R*5 + C`** is the mean of tokens `(2R+r', 2C+c')`, `r', c'` in {0,1}, i.e. indices `20R + 10r' + 2C + c'`. UNVERIFIED: which physical image direction rows and columns are (the feature extractor is not in this tree); the uniform start and control 1 do not depend on it (equal-sized blocks partition the 40 tokens under ANY layout), only the meaning of "cell" does.
* **What a cell is:** the mean of the 2 x 2 block of `adapter(feats) + pos` tokens, i.e. in the same space `WMAux.z1` pools today (`V8FMini._encode`, `ladder/zcache.py` `zmean_of`: `model.adapter(f) + model.pos[None, None]`). Mean over the 10 cells = today's `zmean`.
* **The pool:** one parameter `WMAux.pool_q` `[d = 256]`, ZERO-initialised, built only when `wm_pool == "att25"`, created AFTER every other WM module (no RNG is consumed: zeros). Score `s_k = <cell_k, q> / sqrt(d)` in fp32, `w = softmax_k(s)`, `pooled = sum_k w_k cell_k`, then the EXISTING `proj` (+ `enc1` when K > 1) as `z1_from_mean` does today. At `q = 0`: `w_k = 0.1` and `pooled` equals the global token mean (to fp32 round-off, section 3). No bias, no temperature, no LayerNorm on the cells, no extra input: nothing but the cells enters the pool.
* **ONE spelling:** `WMAux.z1(adapt)` (live adapter tokens, used by the full path and any beta-style planner) builds cells from the tokens (`cells_of_adapt`) and calls `z1_from_cells`; `forward_cells(cells, act)` (the cached path) calls the same `z1_from_cells`. `z1_from_mean` / `forward_mean` RAISE on an `att25` model (a harness that hands a P-ATT model a token mean would silently run the mean pool; it is refused instead).
* **Gradient:** cells are detached cache data (frozen adapter, as `zmean`). `pool_q` is trainable, inside `WMAux`, so `--wm-only`'s "trainable == the WM's parameters" holds by construction. The optimiser/schedule is the base's.
* **Cell cache (box 2 builds it, `theory/wmpool/zcells.py`):** per clip `<dir>/<clip>.npz` with `zcell` **float16** `[T, 10, 256]`, `ok` bool `[T]`, `t_s` f32 `[T]` (same `ok` / `t_s` as `zcache.py`), built from the SAME raw feature cache and the same frozen adapter as `zmean_of` (one extra pooling after `adapter + pos`, before the token mean). Per-clip tmp + rename, resumable. fp16 storage: max abs error about 2^-11 of the value (relative 4.9e-4) per element; the cells are stored in fp16 because 2.36 GB per seed (ESTIMATED, FEASIBILITY) is the size the card budgets; the mean of fp16 cells is compared with the fp32 `zmean` in control 3 and the measured error is stated there.
* **Manifest and adapter sha:** `<dir>/CELL_MANIFEST.json` (written by `zcells.py manifest`): `kind: "zcell"`, `grid: "pool4x10->2x5"`, `n_cells: 10`, `d: 256`, `dtype: "float16"`, the frozen adapter's `adapter_state_sha256` (the same formula as `zcache.adapter_sha`: sha256 over name + shape + dtype + bytes of the sorted keys `adapter.*` and `pos`), `code_commit`, per-file counts and sha256. The trainer refuses unless the manifest's adapter sha equals the sha of the adapter the BUILT model carries (loaded from `--init-ckpt`): a cache of the wrong seed's adapter cannot be used (the same wrong-seed trap `ZCACHE_CHECK12` checks).
* **Refusal without a cell cache:** `att25` with any of: no `--wm-only --wm-windows wmonly`, empty `--wm-zcache`, a directory without `CELL_MANIFEST.json` (e.g. today's mean cache), a manifest of another kind / grid / dtype / d, a missing clip file, or an adapter sha mismatch, exits before the first step with the reason. `--wm-zcache` is REUSED as the cell directory in `att25` (for `mean` it is the mean cache as today); a mean cache handed to `att25` or a cell cache handed to `mean` fails loudly (no `CELL_MANIFEST` / no `zmean` key). The seed-2 replicate takes the `M2b_s0` cell cache, like EGOWM's.
* **G-DVB read-back of the BUILT lever:** `FLAG_CHECKS["wm_pool"] = "lever:wm_pool"` -> `bad_wm_pool(a, cfg, model, data_info)`. It reads `WMAux.built_pool()`, which MEASURES the built module's behaviour: the cell map on a planted `[1,1,40,d]` grid (cell `k` must equal the mean of tokens `20R+10r'+2C+c'`), the weights at the built `q` (uniform for a zero query), the weights on a deep copy with a probe query (must concentrate on the probed cell), `pool_q` shape and zero-ness at build, and the number of parameters. Declared `att25` must read `mode == "att25"` with `n_cells == 10`, one parameter `[256]`, zero at build; declared `mean` must read no module. Also read back from the BUILT dataset: `info["wm_windows"]["pool"]` and the cell shape of a real item. `selfcheck.json` carries `levers.wm_pool_readback` when the argv names the flag.
* **Config validation:** `wm_pool` in {mean, att25}; `att25` needs a world model and `n_tok == 40`.
* **Not touched:** `launch_gate.py` (its owner adds the G-DVB entry; the trainer's `FLAG_CHECKS` entry is in this patch), `stack/tanitad/models/__init__.py`, `hjepa.py`.
