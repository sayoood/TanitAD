# PREREG_LEVELPROBE: H-LEVELPROBE-1, how much of HLVL's M1 closure survives when the level is predicted from the image?

Tier: Stage 1 is a **T0-class probe** (representations on logged inputs, NOT driving performance); Stage 2 is **T1-kin** (self-action open loop on logged cameras; never "closed loop").
Evidence class MEASURED (ours) once read; hypotheses are HYPOTHESES. Written and hashed BEFORE any fit or rollout of this package (`FROZEN_SHA.txt`).
Estimator of every Stage-2 interval: paired episode-cluster bootstrap, B = 2,000, seed 0 (`taniteval.ci` draw stream via `gapdecomp.decompose`); it answers *would another draw of EPISODES say this*, never *would another training run say this* (`H-ESTIM-SEED-1`).

## A. THE CARD (verbatim from the Master Mind's brief; nothing in sections B and C changes a word of it)

**Question.** How much of HLVL's M1 closure survives when the level is predicted from the image?

**Stage 1 (T0-class probe, frozen features, no model training).** Target: the logged speed v_logged at the window's t0. Features: VISION ONLY, the frozen per-window image features of the trigger probes (prefer probe 3's G8 grid, `F:/TanitAD-scratch/trigger_probe3_scratch/G8_{pmove,pstop,eval141}.npy`; establish from `dagland/trigger_probe3/` which windows each row is, and the exact feature definition). No ego, no nav, no speed feature: assert the feature array is the vision grid alone. Model: ridge regression on the flattened (or pooled; state which) features, alpha chosen by episode-grouped 5-fold CV on the TRAIN windows only. The fit never sees an eval-141 window: assert the fit and score episode sets are disjoint. Score on the eval-141 windows: RMSE, MAE, R^2, overall and in the M1 cells. Controls that must read known values: (K1) labels shuffled within the TRAIN set => eval R^2 <= 0.02; (K2) v_logged appended as a feature => eval R^2 >= 0.99 (the pipeline can find a signal when there is one); (K3) the train-mean predictor's RMSE is reported as the baseline.

**Stage 2 (T1-kin rollouts, HISTSWAP-LF machinery).** Two new history-swap levels in the HISTSWAP-LF tool, each a constant-twist history like HLVL, on HISTSWAP-LF's cells and comparators: **HLVL-T0** = logged v at the window's t0, held constant (an oracle; if HLVL itself is already t0-constant this IS HLVL and must reproduce its closure within +-0.02 as a known answer); **HLVL-PRED** = stage 1's prediction for that window, held constant (vision-derived, deployable in kind). Read M1 share closed exactly as the HISTSWAP-LF card defines it, plus the four metric families (LONGITUDINAL, LATERAL, TACTICAL, STRATEGIC; STRATEGIC is reported for v8F) and ADE6, by the paired episode-cluster bootstrap, B = 2,000, seed 0 (the HISTSWAP-LF reader). The tool change must be a new option, with a test that the default path is byte-identical to the shipped tool's output on one window.

**Committed outcomes (both sides, fixed now).**
- **SUPPORTED** (the level-from-image auxiliary earns a PI architecture decision): HLVL-PRED closes >= 0.30 of the M1 excess at >= 3 of the 4 cells, AND its mean closure >= 0.5 x HLVL-T0's mean closure.
- **NOT SUPPORTED**: HLVL-PRED's mean closure < 0.10.
- **INCONCLUSIVE**: anything else. Each outcome is reported with stage 1's eval RMSE and R^2 beside it.
- A HARMS flag is reported beside the outcome: ADE6 (HLVL-PRED - the HISTSWAP-LF comparator) above +0.0604 m at any cell, or any non-crawl row separated-worse.
- **What it cannot claim:** one training run per seed (`H-ESTIM-SEED-1`); a ridge probe's negative is not a negative about learnability (a trained in-model head could do better); T1-kin cameras follow the logged path, so a level predicted from a later frame could carry logged motion. That is why HLVL-PRED uses only the t0 frame.

## B. FACTS ESTABLISHED FROM FILES BEFORE THE FREEZE (they fill the card's brackets; they change no rule)

**B1. The feature array (MEASURED, files read pre-freeze).** `G8_pstop.npy` and `G8_pmove.npy` are `[12000, 163840]` fp16 = the frozen DINOv3-L/16 `pool8x20` token grid (8x20 tokens x 1024, row-major, token index r*20+c) of the CURRENT frame (cache step t) of 12,000 + 12,000 TRAIN windows; row i = canonical window `idx[i]` of `dagland/trigger_probe/raw/sample_{pstop,pmove}.npz` into the 306,566 windows of `dagland/trigger_probe/raw/windows_train.npz` (P-STOP: v0 < 0.5; P-MOVE: 0.5 <= v0 < 6.0). `G8_eval141.npy` is `[608, 163840]`, rows in the order of `dagland/trigger_probe/raw/eval141_features.npz` (`sel` = indices into the 2,399 eval-141 windows of the T1 rig; its clip, t0 and v0 equal the rig's `eid`, `ws`, `v0` on those rows: `raw/F1_coverage.json` checks). The target v_logged(t0) is `windows_train.npz["v0"][idx]` (train) and `eval141_features.npz["v0"]` (eval). Vision-only is enforced by loading ONLY the token arrays into the fit: the ego numbers `E` / `EH`, nav and every other column of `windows_train.npz` / `eval141_features.npz` are never given to the fit; v0 enters only as the label (and, in K2, as the deliberate leak).
**B2. Pooling (stated choice).** The 163,840-d flatten does not fit this box's free memory (5.5 GB free of 31.8 GB at the freeze); the ridge uses the **G2x4 pooling = the mean of each 4x5-token block of the 8x20 grid (2 rows x 4 columns of blocks) x 1024 channels = 8,192 features**, computed in float32 as the mean of probe 3's exact `G4` (`g_lib.g4_from_g8`, 2x2 mean) over 2x2 blocks of G4 cells. No scaling beyond centring.
**B3. Ridge and folds (stated choice).** Primal ridge on centred features and centred labels (intercept unpenalised). alpha = c x (trace(X^T X) / D) over c in {1e-3, 1e-2, 1e-1, 1, 10, 100, 1000} (D = 8,192; the trace is that of the fold's own centred training matrix), chosen by minimum pooled out-of-fold RMSE of an **episode-grouped 5-fold CV on the TRAIN windows only**; folds = `int(episode_sha12, 16) % 5` of the window's clip (the probes' own `outer_fold`). Refit on all 24,000 TRAIN windows at the chosen c; applied unchanged to the eval windows. The controls run the SAME pipeline, including the alpha search.
**B4. Disjointness.** Train clips come from the TRAIN corpus (4,512 clip names in `windows_train.npz`), eval clips from the 141 eval-141 clips; the fit/score clip-name sets are asserted disjoint and the assertion is logged.
**B5. "The M1 cells" in Stage 1 (stated reading).** The four rig cells (DAG-OACC s0/s1, SOUP s0/s1) share one window set (the 2,399 windows), so Stage 1's "M1 cells" = **the M1 windows**: eval windows with a finite M1 share (>= 1 GT-fast pair; `kappa_t1/raw/arrays/SREP_DAGOACC_s0.npz` row `M1 crawl share`: 2,104 of 2,399 windows, 313 of the 608 v0 < 6 windows) and the `gapdecomp.classify` classes L / S / O / M within the scored windows. Scores are reported overall, on the M1 windows, and per class.
**B6. K2 construction.** The appended v_logged column is standardised (train mean / std) and multiplied by sqrt(trace(X_c^T X_c) / N) so that its own variance equals the mean squared per-window feature norm; it goes through the same ridge and alpha search.
**B7. What HLVL is (MEASURED, `histswap_lf/code/apply_lf_patch.py`).** HISTSWAP-LF's `cv_logged` (HLVL) uses the LOGGED measured speed **at every tick** (`base_log["p10f"][j][0]`), NOT the t0 value. HLVL is therefore NOT t0-constant, so the card's conditional known answer ("if HLVL itself is already t0-constant ...") does not apply; HLVL-T0 is a new, weaker oracle (the level at t0 only, no later logged speed). Its closure is reported beside HISTSWAP-LF's HLVL closure (0.599 to 0.633 per cell, MEASURED in `histswap_lf/raw/HISTSWAP_LF_T1.json`) for context, and no pass/fail is attached to the comparison.
**B8. Cells and comparator (MEASURED, `histswap_lf/histswap_lf_chain.sh`).** The 4 cells = DAG-OACC s0/s1, SOUP s0/s1 (checkpoints and trees as in that chain). Y = KAPPA-T1's `SREP_*` runs (reused; "the HISTSWAP-LF comparator"); the HARMS ADE6 guard (+0.0604 m) is read on X - Y exactly as in HISTSWAP-LF.

## C. PRE-FREEZE FINDING F1, WHICH BLOCKS STAGE 2'S HLVL-PRED AS WRITTEN (reported, not repaired)

**F1 (MEASURED, `raw/F1_coverage.json`).** Probe 3's features exist ONLY for windows with v0 < 6 (24,000 train windows; 608 eval windows). The T1 rig rolls out 2,399 windows; **1,791 of them (74.7 %) have v0 >= 6, and they are 1,791 of the 2,104 M1 windows (85.1 %)** (313 M1 windows have v0 < 6). Of the 301 windows with a non-zero Y M1 share, 190 have v0 < 6 and 111 have v0 >= 6. A ridge trained on v0 < 6 labels cannot predict the level of a v0 >= 6 window (the label never leaves [0, 6)), and the card defines HLVL-PRED as "stage 1's prediction for that window" with no rule for the windows stage 1 has no prediction for.
**Consequence under the brief's own instruction ("if a fact makes a rule impossible as written, STOP and report it rather than changing the rule"):**
* **Stage 1 is executed AS WRITTEN** on the windows that exist (24,000 train, 608 eval), and reported with its coverage next to every number.
* **HLVL-T0 is executed AS WRITTEN** (it needs no vision feature and is defined on all 2,399 windows).
* **HLVL-PRED is NOT launched.** The card's committed outcome (SUPPORTED / NOT SUPPORTED / INCONCLUSIVE) is therefore **NOT DEFINED as written**; no outcome is stated in this package. A proposed amendment (A1: extend the feature extraction to all 2,399 eval windows and to v0 >= 6 train windows, from the same caches with the same feature definition) is written separately in `AMEND_A1_PROPOSED.md`; it is NOT part of this frozen card, is not executed, and would be frozen under its own hash before any fit on the extended population.
