## Decisions
* Q1 REVIEW The head. "A head of the same shape as the gap branch of the banked head": a whole fresh head, per-frame Linear 640 to 64, concatenation of the 5 frames, Linear 320 to 128, GELU, Linear 128 to 1 (the banked LeadSupHead, tree `stack/tanitad/models/v8f_mini.py` lines 814 to 830, with 1 output instead of 3). Read alternative rejected: only the last Linear 128 to 1 on the banked trunk (it would share the banked head's weights, which the card keeps unchanged). The real head has 640*64+64 + 320*128+128 + 128+1 = 82,241 parameters (the banked head, 82,499, has 258 more for its two extra outputs).
* Q2 The state input. The 5 level-1 states z1 of frames t-4 to t, raw (no normalisation, as the banked head), end frame t. In the fit: the rows of the state file `<ARM>_train.npz` (float16 as extracted, cast to float32 per batch; the banked head saw float32 in training: stated limit). In the rollout: `model.wm.z1(model.adapter(feats[:, -5:].float()) + model.pos[None, None])`, the expression of `v8f_t1_eval_rule.head_values` (the banked read is called unedited; the quantile head is applied to the same z1). A cache stored as float8 is sliced and cast with `.float()` before any use (a test runs a float8 batch).
* Q3 Rows (card section 3). State rows (clip, t) with 4 predecessors t-1 to t-4 of the same clip, matched to the train pack by clip name and frame, presence 1 and a finite gap label (any distance: the pack holds the join's 0 to 60 m labels). MEASURED on this box, LS_s0: 32,025 rows, equal to the card's figure (`state_rows 121,166, with_history 116,366`).
* Q4 REVIEW Recipe of the banked head. The banked head was trained inside the model's trainer (`stack/scripts/v8f_mini_train.py`), not on frozen states: AdamW, lr 3e-4 (line 302), weight decay 1e-2 on parameters with ndim >= 2 and 0 on the others (lines 2840 to 2848), warmup 200 (line 304) then cosine to 0.1 x lr (class LRSchedule, lines 757 to 766), gradient clip 1.0 (line 305), batch 64 (line 300), steps = the checkpoint step 19,164 of the four arms (`spatial/leadsup/read/in/LSD_s0_train_lead.npz.json`, `step`; trainer line 2849 to 2850), raw states. All reused; the loss line is the only difference: banked line `v8f_mini.py:796` (Huber of gap/50 on frames with a gap label) becomes the pinball loss at 0.20 of gap/50 (`qhead_fit.py`, line marked `# LOSS`). The one thing that cannot be identical: the banked head trained on windows of 16 frames (12 end frames each, all labelled frames) with the model; the fit samples single end-frame rows, shuffled in epochs of the fit rows, batch 64 rows.
* Q5 Loss. Pinball at 0.20 on gap/50 m (the scale of the banked outputs), mean over the batch rows; the output estimates the 20 % quantile, so the share of rows with q_head above the label gap is 0.20 at the optimum (the card's coverage).
* Q6 Seed. `torch.manual_seed(seed of the base)` immediately before building the head (seed 0 for LS_s0 and LSD_s0, 1 for the s1 arms), the row sampler `RandomState(seed)`. The draw order of the banked head inside the model init is not reproducible and not claimed.
* Q7 Held-out clips. The last 200 clips of the state file's clip list (manifest order; the pack's clip list must equal it, else the fit refuses): state-file clips 1000 to 1199. MEASURED LS_s0: 26,327 fit rows, 5,698 held-out rows. The held-out rows are used only for coverage (control h5), never in the fit; the fit record carries `fit_clip_max_index` and `held_clip_min_index`.
* Q8 Gap used. `g_used = min(g_head, q_head)` per tick, no clip at 0 (the card gives none), a quantile that is not finite leaves the head gap, a head gap that is not finite stays as it is. Presence, closing speed and the all-frames-real flag are the banked head's. The rule is the all-head mix of card ADD29 with the threshold P of the arm (card ADD31 values 0.4, 0.5, 0.4, 0.3 in `qhead_arms.txt`; the control 0.5), floor `cap-only` as in the QC arms.
* Q9 Control rollout `LSQHI_s0`: `--q-equals-head` makes q_head the head read itself; `min(g, g)` is `g` bit for bit; control h1 compares its dump with the banked head-fed dump `LSRH_s0` through `cmp_dumps.py` (0 files differing). The queue stops (QHEAD_STOP.txt) if h1 fails: the four rollouts would carry no meaning.
* Q10 Logging for h3. The rule log of the base tool is untouched; the tool writes beside it `rule_log_<ARM>_qh.npz` with, per planner call and row for row with the rule log: `g_head`, `q_head`, `g_used`, `p_head`, `ok`, and a meta (mode, P, head file sha256). The alignment is by call order; `qhead_h3.py` refuses when the row counts differ.
* Q11 REVIEW Control h3 (qhead_h3.py). First tick = `k == 0` of the rule log; present = the rule log's `present`. The state row of a tick is (clip name `join["clip"][ci]`, frame t = `j`), history t-4 to t in the eval state file; this mapping (state frame index = cache row index j) is assumed and is checked by the count of matched rows (a mismatch fails the control). Card form (b): `g_src` against `min(g_head, q_head)` recomputed from the eval states with the banked head tensors (`<ARM>_eval_lead.npz.head.npz`) and the quantile head, within 1e-4 m. The eval state file holds float16 states, the rollout float32: if (b) fails by rounding alone, (c) shows the head-gap difference of the rollout against the recomputation; PASS stays the card's literal bar and the lead decides, not the script. (a) checks the wiring inside the rollout.
* Q12 Control h2: the sum of the `lift` column of every rule log of this card (four QH arms and the control) is 0 and the log is not empty.
* Q13 Control h4: the fit refuses a path whose basename or parent folder name carries `eval`, requires the state-file record to say `split` train, and writes every file read with its sha256 (`files_read_sha256`, `q4_only_train_files`). The tool refuses a head file of an evaluation path and a head file whose sha256 differs from its fit record, and a head fitted on states of another checkpoint than the `--ckpt` of the run (the record carries the state file's checkpoint sha256).
* Q14 Control h5: coverage = share of held-out rows with q_head strictly above the label gap, in [0.15, 0.25] for every checkpoint; recorded as `h5_coverage_in_0.15_0.25` in each fit record. A fit that misses it is still written (exit 0) and `qhead_names.py` then names nothing.
* Q15 Control h6: the tests (`test_qhead_fit.py`): gradient on every parameter of the new head non-zero, exactly 0.0 on a control parameter outside the graph and on all six banked-head tensors; planted states (known gap, noise 0.1 x gap x u with u a per-clip code held in a state direction the gap read does not hold): held-out coverage 0.20 within 0.03 and 0.20 within 0.05 in each noise group; the mutations of `run_mutations.py` (19 source-line mutations, each named test must go red; the unmutated suite must stay green). The fit also runs the gradient check on its first batch before training and refuses to continue if it fails. `MUTATIONS_QHEAD.json` is read by `qhead_names.py` as the h6 evidence (`all_ok`).
* Q16 Read. Pairs of section 5 (arm base names, seeds 0 and 1): headway r2 `LSQH:LS, LSQH:LSRH, LSQH:LSRL, LSQH:LSMC, LSQH:LSQC` and the same for LSD; q3 r2 `LSQH:LS, LSQH:LSQC, LSQH:LSMC` (+ LSD), `--same-sign`, spread arm G with six seeds, as card ADD31. Share reached per base = (U(none) - U(QH)) / (U(none) - U(RL)) from the per-base U of the headway levels.
* Q17 Names (`qhead_names.py`, section 7), both seeds needed. REACHES-ORACLE: share >= 0.5 in both bases AND the upper end of the two-level interval of U(QH) minus U(none) below 0. Against the map: U cell and the position error over 6 s on all windows (`ade6_m|all` of the family reader), each "in both seeds below 0 (above 0) with an interval excluding 0" means both per-base differences on the same side and `A_excludes_0`. Cost against no rule (card ADD11): the family reader's name `NO-COST` gives QHEAD-NO-COST, any other gives QHEAD-COSTS with its cells. Beside, naming nothing: U and contact against RL and MC, the first-tick mean amount taken off the read and the coverage on the evaluation windows (from the h3 files).
* Q18 Pod placement. The tool files go next to the banked tools in `/workspace/v8proof/distrule/` (the derived run script checks `dist_rule.py` beside itself, as for card ADD31); the queue derives `pod_qhead_run.sh` from `pod_ruleattr_run.sh` by one sed (`--head-p-min $4 $5 $6` in front of the argv), fails closed if the result is not as expected. The fits run on the CPU by default (`QH_DEVICE`), after a slot wait like the rollouts.
