# CAND10K_DEFS.md -- what each read, control and name of card PREREG_V8F_PROOF_ADD65 is computed from

Tier of every rollout number: T1-kin (kinematic rollout on the model's own actions; the lead does not react and follows its logged track); never driving performance. Reader: `read_cand10k.py` (numpy only), run on the pod by `podread_cand.sh` after control e1. The card is `PREREG_V8F_PROOF_ADD65` and is not edited here.

## Tools

* Wrapper `v8f_t1_eval_reader_rule_rzgf.py` = `v8f_t1_eval_reader_rule_rzf.py` (sha256 prefix 51b3e783536689f6, asserted; card ADD62, `--rule-every h`) plus the readout edits of `make_accgain10k.py` (card ADD63: readout `causal_g`, `--acc-gain G`, `--path-exec`), written by `make_cand10k.py` with asserted text edits (each old text exactly once). Nothing else is added. Readout K = `--readout causal_g --acc-gain 0 --path-exec`; the second look = `--rule-every 5`. The pinned tool is imported by path and not edited.
* Tool checks (control c6): `check_rule_every_rzgf.py` and `check_acc_gain_rzgf.py` are copies of `check_rule_every.py` and `check_acc_gain.py` with the wrapper name as the only change (`rzf` / `rzg` to `rzgf`); both run on the pod CPU against the combined wrapper. Outputs of the pre-run on the pod CPU: `read_cand/CHECK_RULE_EVERY_RZGF.txt`, `read_cand/CHECK_ACC_GAIN_RZGF.txt` (the queue writes its own copies into `$W/cand_test/`, marker `ck6check`).
* Queue `pod_cand10k_queue.sh` (waits for `ACCGAIN10K_DONE.txt` or `_STOP.txt`; `WAIT_MAX`, default 86400 s): the two tool checks (marker `ck6check`); control `I10R0KID` (no rule, readout K, model seed 0) compared by `cmp_dumps.py` with the banked dump of `I10R0G0X_s0` (marker `ck1cmp`, file `small_cand/CMP_R0KID.txt`); control `I10RLcKIDp` (label-fed, pinned readout, `--rule-every 5`, model seed 0) compared with the banked dump of `I10RLcF5_s0` (marker `ck2cmp`, file `small_cand/CMP_RLcKIDp.txt`); then at both model seeds (reader seed = model seed) `I10RLcK`, `I10RQ50K` (rule at the tick), `I10RLcKF5`, `I10RQ50KF5` (rule every 5 steps), all with readout K. Ten rollouts in all. The rule form, reader checkpoint, map at level 0.50 (closing 0 for the reader form), rule parameters and the slot rule (MAXGPU 3, MINGB 28) are those of the ADD62 queue. Markers `START_CAND10K.txt`, `CAND10K_STOP.txt`, `CAND10K_DONE.txt`. Each `ticks/run_<arm>.txt` carries the checkpoint sha256, the wrapper sha256, the rule rate and the readout.
* Chain `chain_cand10k.sh` (push with sha256 compare, start, poll 72 h, pull), pod read `podread_cand.sh`, dev-box waiter `wait_podread_cand.sh` (results to `read_cand/pod/`).
* Reused runs (hashed on the pod before the queue: `CAND10K_REUSED.json`, list in `CAND10K_REUSED_FILES.txt`, 24 files): `I10R0`, `I10R0G0X`, `I10RLc`, `I10RQ50`, `I10RLcF5`, `I10RQ50F5` at both model seeds (result files for all; rule logs for the four rule runs; reader side files for the two reader runs).

## Reads (paired episode-cluster bootstrap of the headway and family readers, pooled over the two model seeds, per-seed values beside)

* Per form (LABEL = `I10RLc...`, READER = `I10RQ50...`): RK = rule at the tick (K) minus `I10R0G0X`; FK = rule every 5 (K) minus rule at the tick (K); CC = rule every 5 (K) minus the convention run (`I10RLc` / `I10RQ50`). U, C, F and the ten family cells for every pair; the named cells per family never pooled.
* Beside, names nothing: (rule at the tick, K) minus the convention run; (rule every 5, K) minus `I10RLcF5` / `I10RQ50F5`; `I10RQ50KF5` minus `I10RLcKF5`; the whole candidate minus `I10R0` (pinned readout, no rule). For READER pairs a pooled U difference of at most 0.0196 in absolute value is flagged `U_inside_reader_floor_row106`.
* Names per form (card section 6): `CAND10K-<form>-RULE-CUTS-UNSAFE-UNDER-K` / `-RULE-NOT-SEPARATED-UNDER-K` (RK: below 0 at both model seeds and the pooled interval below 0); `-SECOND-LOOK-CUTS-UNSAFE` / `-RAISES-UNSAFE` / `-NO-U-CHANGE` (FK: one sign at both seeds and the pooled interval on that side of 0); `-U-BELOW-CONVENTION` / `-U-ABOVE-CONVENTION` / `-U-NOT-SEPARATED-FROM-CONVENTION` (CC on U, same way); `-<FAMILY>-BETTER-THAN-CONVENTION` / `-WORSE-THAN-CONVENTION` / `-MIXED` / `-NOT-SEPARATED` (CC, family rule as card ADD63: named cells LONGITUDINAL speed error and along-track error, LATERAL heading error and yaw-rate error, TACTICAL tactical ADE; BETTER if every named cell reads BETTER, WORSE if every one reads WORSE, NOT-SEPARATED if none reads either, else MIXED). STRATEGIC: as note N1 of card ADD46 (NOT COMPUTED along the rollout, n = 0).
* The consequences fixed in section 6 of the card are listed mechanically per form under `reported_no_bar.consequences_fixed_by_card_section_6_per_form`; the read itself changes nothing.
* Reported without a bar: later looks that changed the plan and that reached the braking limit on a step still to be driven (per run), the saturated executed steps of the tick rows beside those of the banked run, RS (share of the 2,399 windows ending more than 5 m/s above the logged speed) per run, the acceleration read of the K runs.

## Controls (all must pass; else no name, no level, no difference)

* e1 the pod read reproduces the banked dev-box read of card ADD46 leaf for leaf (`ENV_E1.json`).
* c1 `CMP_R0KID.txt` reads 141 files, 0 differing. c2 `CMP_RLcKIDp.txt` reads 141 files, 0 differing.
* c3 readout log of every K run (five runs incl. the control): readout `causal_g`, gain 0, path_exec true, rule form as expected, 10 steps, calls above 0, largest difference speed at the last executed knot minus last executed step speed and acceleration read minus gain times executed at most 1e-6; the rule log carries the form, and for the rule-every-5 runs the later-look log carries `rule_every` 5; the run record carries the rule rate.
* c4 for `I10RLcK`, `I10RQ50K`, `I10RLcKF5`, `I10RQ50KF5` at both model seeds: executed steps 1 to 10 equal those of the banked `I10RLc`, `I10RQ50`, `I10RLcF5`, `I10RQ50F5` (largest difference 0.0 on the dump array `cl`, same windows); the tick-0 rows of the tick log equal the banked rows in present, g_src, c_src, v_l, a_l, a_m, g0, v0, v_L, active (at most 1e-9).
* c5 largest `excess` over all later looks of every rule-every-5 run (including the control `I10RLcKIDp`) at most 1e-9 m.
* c6 both tool-check outputs end with their `all hold: True` line (the rule check has three k5 lines that hold, the planted fault failing the direction check; the gain check has both planted faults caught), and the wrapper of the runs, the copy the checks ran with, the sha256 both checks printed are one sha256.
* c7 counts: 141 dump files per new run, 2,399 windows, 642 lead windows, tick rows = windows x 3, later-look rows = windows x 3 for the rule-every-5 runs, no later-look file for the tick runs. c8 the 24 reused files hash as recorded. c9 the reader controls of the headway and family readers. c10 checkpoint sha256 prefixes of each new run equal those of card ADD46; the wrapper sha256 of the runs equals the one the checks ran with and has the prefix recorded in the reader.
