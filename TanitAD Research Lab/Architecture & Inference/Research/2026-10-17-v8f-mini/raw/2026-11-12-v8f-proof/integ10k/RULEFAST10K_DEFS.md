# RULEFAST10K_DEFS.md -- what each read, control and name of card PREREG_V8F_PROOF_ADD62 is computed from

Tier of every rollout number: T1-kin (kinematic rollout on the model's own actions; the lead does not react and follows its logged track); never driving performance. Reader: `read_rulefast10k.py` (numpy only), run on the pod by `podread_rulefast.sh` after control e1. The card is `PREREG_V8F_PROOF_ADD62` and is not edited here.

## Tools

* Wrapper `v8f_t1_eval_reader_rule_rzf.py` = `v8f_t1_eval_reader_rule_rz.py` plus `--rule-every h` (default 10), written by `make_rulefast10k.py` with asserted edits (each old text exactly once). The pinned tool is imported by path and not edited. Forms RLb, RLc and RR only; below the replan interval it needs `--rule-log`, a divisor of the replan interval, and no acceleration limit (refused otherwise). A value at or above the replan interval installs nothing and writes nothing new.
* The later looks (function `mid_looks`) act on the plan after the rule at the tick, for q = h, 2h, ... below the replan interval m. Per look and window: the car is at knot q of the plan built so far, taken to the t0 ego frame with the arithmetic of `floors_kin.gt_waypoints` on the world position of the knot (`plan_to_world`, mirrors `RulePlanner.__call__`: progress a_m = `R.progress(g_log, pos)`, logged arc a_l = `R.logged_arc(g_log)[k + q - 1]`, logged speed `logged_v[j + q]`); the source read at frame j + q by the same combination code as `MixPlanner` (label read `LabelSource.read(ci, j + q)`; reader: the tokens of the cache steps j + q - 4 .. j + q of the window's own clip, `frame_ok` as the item builder gives it: real frames and finite p10f for rows already in the window state, later rows taken as the executed rows a real tick would have; the gap through the same map; presence = probability at least 0.5 and a full history); the car's speed v0 = the chord speed of the last step before q (|knot q - knot q-1| / 0.2 s, knot 0 = the tick origin); g0 = g_src + a_l - a_m; v_L = max(0, v_l + closing). The remaining knots are taken relative to knot q (the rule works on arc lengths along the path, a translation changes nothing); the executed-step count is m - q; the same rule parameters and the floor form cap-only as the tick. Steps up to q are never changed; a later knot the rule leaves unchanged stays the original float32 value; a changed knot is the float64 rule output plus knot q, rounded to float32 like the tick output.
* Logs per run (folder `t1/<run>_s<k>/ticks/`): `rule_log_<run>.npz` (tick rows, unchanged: one row per window and tick); `rule_log_mid_<run>.npz` (one row per window, tick and later look: the columns of the tick log, with j and k the frame and step of the look, `tick` the block, plus `q`, `excess` = largest arc coordinate of the new knots on the path before the look minus the old arc, float64, before rounding, and `nchg` = knots changed; meta incl. `rule_every`, `mid_envelope_hits` = plans the pinned tool's step envelope would reshape, reported not acted on); `rule_log_mid_<run>_rd.npz` (reader reads of the looks, row for row; reader form); `p1_first_<run>.npz` (the plan after the rule at the first tick, the reference path of the second clause of control k4). Run names: `I10RLcFID` (control k1), `I10RLcF5`, `I10RQ50F5`, `I10RLcF2`. Reused: banked `I10R0`, `I10RLc`, `I10RQ50` and, control k3 only, the rule logs of `I10RLcM5`, `I10RQ50M5`.
* Queue `pod_rulefast10k_queue.sh` (waits for `CAUSLIM10K_DONE.txt` or `_STOP.txt`; `WAIT_MAX`, default 86400 s): tool check `check_rule_every.py` (marker `rf9check`), `I10RLcFID` then the compare marker `fr1cmp`, then at both model seeds `I10RLcF5`, `I10RQ50F5`, then `I10RLcF2`. Slot rule unchanged. Each `ticks/run_<arm>.txt` carries the checkpoint sha256, the wrapper sha256 and the rule rate.

## Reads (paired episode-cluster bootstrap of the headway and family readers, pooled over the two model seeds, per-seed values beside)

* FR per form = U(rule every 5) minus U(banked): LABEL `I10RLcF5` minus `I10RLc`, READER `I10RQ50F5` minus `I10RQ50`; contact C and falling behind F of the same pair beside; the family cells (LONGITUDINAL, LATERAL, TACTICAL) per family, never pooled. Dose: `I10RLcF2` minus `I10RLc` and minus `I10RLcF5`. Beside: each new run against `I10R0`; `I10RQ50F5` minus `I10RLcF5`.
* Names per form: `RULEFAST10K-<form>-FASTER-RULE-CUTS-UNSAFE` (U below 0 at both model seeds and the pooled interval below 0), `...-RAISES-UNSAFE` (above 0 at both and the interval above 0), else `...-NO-U-CHANGE`. STRATEGIC: as note N1 of card ADD46 (NOT COMPUTED along the rollout, n = 0).
* Reported without a bar: per run and model seed, later looks, those with a lead present, those that changed the plan, those with a saturated step still to be driven (`sat_exec` > 0, executed-step count m - q), and the saturated executed steps of the tick rows beside the banked run.
* Split of the windows that stay unsafe: `unsafe_cause_f5.py` (generated by `make_unsafe_cause_f5.py`), descriptive, names nothing; for the runs with later looks also the rule state at the later look in force.

## Controls (all must pass; else no name, no level, no difference)

* e1 the pod read reproduces the banked read of card ADD46 (`ENV_E1.json`). k1 `CMP_RLcFID.txt` reads 141 files, 0 differing.
* k2 executed steps 1 to h of `I10RLcF5` / `I10RQ50F5` (h = 5) and `I10RLcF2` (h = 2) equal those of the banked run of the same form and model seed (largest difference 0.0 on the dump arrays `cl`); the tick-0 rows of the tick log equal the banked rows in present, g_src, c_src, v_l, a_l, a_m, g0, v0, v_L, active (at most 1e-9).
* k3 the first-block look at q = 5 against the row of the banked 5-step run (`I10RLcM5`, `I10RQ50M5`) at k = 5, matched by window. Log-only inputs (presence, source gap, source closing, logged speed, logged arc; for the reader form also the reader probability, gap read, gap used and the full-history flag) in ALL windows; the inputs that depend on the driven steps (progress a_m, corrected gap g0) on the windows where the first five executed steps of the banked 2.0 s run and of the banked 5-step run are equal; both counts are printed per run. At most 1e-6.
* k4 first clause: largest `excess` over all later looks of every run at most 1e-9 m (measured on the float64 rule output). Second clause: rule every 2 never ahead of rule every 5 at the first tick's block, per model seed, label form: the arc coordinate of the executed knots 1 to 10 on the first-tick plan `p1_first` (`path_arcs`); the card gives no tolerance, 1e-4 m is used (float32 knots) and the per-step largest excess and the number of windows ahead are printed. Not exercised here on real data.
* k5 the tool check output on the pod (`CHECK_RULE_EVERY.txt`: three k5 lines hold, the planted fault fails the direction check, last line `ZZ CHECK-RULE-EVERY all hold: True`).
* k6 counts: 141 dump files per new run, 2,399 windows, 642 lead windows, tick rows = windows x 3, later-look rows = windows x ticks x (10 / h - 1), no later-look file for `I10RLcFID`. k7 the 18 reused files (6 result files, 12 rule logs) hash as recorded in `RULEFAST10K_REUSED.json`. k8 the reader controls of the headway and family readers. k9 checkpoint sha256 prefixes of each new run equal those of card ADD46; the wrapper of the runs, the copy the tool check ran with, the sha256 the tool check printed and the `run_<arm>.txt` records are one sha256, with the prefix of the card.

## What was NOT exercised

* The wrapper has not been run on the model, the cache or the eval windows; the reader has not been run on any data (only `--help`, rc 0); the queue, chain and waiter have not been started. The pod tool check drives the real `ReaderPlanner` on synthetic circular-road windows with the real `LabelSource`, the real pinned `plan_to_world`, `envelope` and `floors_kin`, and a fake token reader; it does not exercise the real reader checkpoint, the real map files, the batch collation of the pinned tool, or `frame_ok` rows that are not finite.
