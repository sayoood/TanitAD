## 0. FIRST: clauses of the card that could fail by construction, and what the code cannot do as written

1. **REPLICATED needs two separated intervals from about 650 windows.** The card's name rule makes `VISREP10K-REPLICATED` require VD5cx `CUTS-CONTACT` (upper end of C(VD5cx) minus C(RR) below 0) AND `WITHIN-HALF-THE-GAP`. Not a control, a name rule: it is applied as written.
2. **`NOT-REPLICATED` is wider than "half the gap not reached".** Read literally ("HALF-THE-GAP-NOT-REACHED, or is not CUTS-CONTACT"), a VD5cx that is `CONTACT-NOT-SEPARATED-FROM-RR` or `MORE-CONTACT` is NOT-REPLICATED even when it is WITHIN-HALF-THE-GAP. `REPLICATION-NOT-DECIDED` is then only reachable with CUTS-CONTACT and `HALF-THE-GAP-NOT-DECIDED`. Implemented as written (`replicate_name`, `card_check` re-derives it a second time and the names stage refuses on a mismatch); pinned in `test_the_replicate_name_follows_the_card_word_for_word`.
3. **w0 inherits the point of card ADD101 section 0.1:** a dump with more token frames than the join has frames fails w0 by construction (`n_frame_count_mismatch_clips`, `n_dump_rows == n_join_rows`, 141 clips in the join order). D-H1 comes from the same `crop_dump.py` as D-H5 (which passed it for card ADD102), so it is not expected to fail, but I could not look at the dump. D-H1 has an output on every frame (`crop_dump.py:34`), so `n_without_output` is 0 for it; the build check needs only `n_with_output > 0` (tested with a synthetic dump that has an output on every frame).
4. **w2, VRc against V0.** Every lead row of VRc is held to a V0 value of card ADD102 at the same (clip index, frame), any of the V0 values within 1e-3 m (V0 can log a frame twice). A VRc lead row at a key V0 has no row for fails w2 (`n_ref_missing`). Expected not to happen (presence and keys depend on the logged frames and the fixed looks, not on the rolled-out ego), but the closing switch changes the ego path, so I name it. Where the card says "the same test against V0" for a lead row with no head output in VD5cx and VD1c, I use the same 1e-3 any-value test (the reader of card ADD102 used 1e-4 against one value).
5. **w1 is a control the reader of card ADD102 only noted.** Implemented as: the file given in `--wrapper-file` hashes to 28bc31f21ecb4ccb; the last line of `CHECK_WRAPPER_V_DONE.txt` is `ZZ CHECK-WRAPPER-V PASS`; `CHECK_WRAPPER_V.hashes` names the hash. One addition not in the card: every `run_*.txt` of the six rollouts must name a wrapper sha256 starting with that hash (six expected; fewer found fails). The queue writes those files for every rollout.
6. **w5 inherits an unverified point of card ADD102 (its DEFS 0.7):** whether an engine control inside `ALL_PASS` assumes a zero closing column for RR-form rule logs. The engine now reads 11 runs (six new, RR, RLc, KD5, VD5c, VD5). I could not run it.
7. **Falling behind "by more than 10 m"** is the engine's F rate (`R.ucf`), as in card ADD102; I did not re-derive the 10 m threshold.
8. **H.** The names use H = half of the point value of C(RR) minus C(RLc) (0.0477 as the card prints it); `h_note` in the names result gives both and flags a difference.
9. **Not done by code (lead):** freezing the hash file, logging the controls in `TIMES_NOTE.md` before the names, running the pytest on the dev box (w4 reads the text of `lead_pytest.out`: "N passed" and no "failed"/"error").
10. With one control failed nothing is opened: the names stage refuses unless w0 to w5 are all present and PASS; the controls stage writes the values under `withheld` when any control fails.

## 2. Definitions with sources
* **VGAP1 files** (`make_rep_gapfile.py:build_arrays`, unchanged from card ADD102): one row per join frame, `clip_index`, `frame`, `gap` (the head's output as dumped, NaN where none), `has_out`, `clips`, `seed`; dump `<dump-root>/D_H1/reader_s<k>_score.npz` (`cropread/fit/crop_dump.py:80`, head H1 at `:34`, `:45`); model seed k reads fit seed k. No map, no clip, no minimum.
* **w0 record** (`build()`): `v0` (the dumps are on the frames of the join, 141 clips, same order), `build` (saved gap equals a second routine within 1e-9, output flag is finiteness), `add102` (`add102_check`: `VGAP_s0.npz`, `VGAP_s1.npz` in `--add102-gap-dir` have the `files.<name>.file_sha256` of that folder's `VISRULE_GAPFILES_RECORD.json`, whose card must be ADD102), `w0` = all three. The reader's w0 repeats it on disk, requires the same ADD102 file hashes the record saw, the VGAP1 hashes of the record and the evaluation join hash.
* **Arms** (`pod_visrep10k_queue.sh`, last rollout lines): per model seed k, form RR, reader `lr16/TK16_s<k>`, q50 map, arguments of the VD5c call of card ADD102 plus the closing switch:
  VD5cx = `VGAP=$G2/VGAP_s$((1 - k)).npz VCLOSE=1` (the ADD102 gap file of the other fit seed); VRc = `VCLOSE=1` only; VD1c = `VGAP=$GF/VGAP1_s$k.npz VCLOSE=1`. Run folders `integ10k/t1/I10RQ50KF5P30Hb20w<ARM>_s<k>`. With no gap file the wrapper's `vis_replace` leaves the reader's own gap (`...tjv.py:1460`) and `--vis-closing` makes the closing input the slope of it by the label source's run rule (`vis_run_closing`, `:1486`).
* **Admission** (queue): wrapper 28bc31f21ecb4ccb with the pod check record of card ADD102 (`visrule10k/check_v`); `visrule10k/gapfiles` record with `v0`, `build` PASS and both gap file hashes; `$GP/gapfiles/VISREP_GAPFILES_RECORD.json` with `v0`, `build`, `add102`, `w0` PASS and both hashes and the evaluation join hash; banked runs RR, RLc (dump folders), KD5, V0, VD5, VD5c (T1_DONE), both seeds; the pinned tool, overlay tree, checkpoints, grid, join, cache as in the ADD102 queue.
* **Controls** (`read_visrep10k.py`): w0 `ctl_w0`; w1 `ctl_w1`; w2 `w2_one` / `w2_from_files` (per rollout, tick log and later-look log together: VD5cx against D-H5 of fit seed 1-k, VD1c against D-H1 of fit seed k, both within 1e-3 m; VRc and no-output rows against all V0 values within 1e-3 m; meta `vis_gap_file_sha256` = ADD102 record's `VGAP_s<1-k>` for VD5cx, this record's `VGAP1_s<k>` for VD1c, the empty string for VRc, `vis_closing` 1 in all; closing input non-zero on a positive share of lead rows; lead rows present); w3 `ctl_w3` (RR 0.0954, RLc 0.0000, KD5 0.0169, VD5c 0.0169, VD5 0.0769, four decimals, from the banked rollouts); w4 `ctl_w4`; w5 `ctl_w5` (grid ALL_PASS, strategic stages A and B).
* **Names** (`names_of`, `gap_name`, `slope_name`, `replicate_name`): per arm four (`CONTACT` vs RR, `HALF` vs RLc with H, `VD5C` vs VD5c, `PRICE` falling behind vs RR) and the card names `CARD_REPLICATE` (from VD5cx), `CARD_GAP` (pair VD5c minus VRc, banked VD5c of card ADD102 against new VRc), `CARD_SLOPE` (pair VD5c minus VD5, both banked). Intervals: the engine's paired differences, two-level bootstrap over model seeds and episodes, 2,000 draws (`--n-boot`; the engine controls of the controls stage use 300 as in ADD101/102).
* **Printed with no name** (payload and stdout): unsafe rate, levels per model seed, falling behind against RLc, share of rule steps with a lead and share of lead steps with a non-zero closing input per rollout (six rollouts), the pairs of the three arms against KD5, the pairs VD5c-VS-VRc and VD5c-VS-VD5 with C, U, F.
* **Families:** LONGITUDINAL (C, U, F, the engine's pair read), LATERAL and TACTICAL (engine pair read, every pair incl. against VD5c), STRATEGIC (engine strategic grid with its own controls; every arm against RR, RLc and VD5c).
* **Readings committed in advance:** card section 3, last paragraph; not coded.
