## A. The actions of a candidate (card section 2: "by the same definition that gives the logged actions of the corpus")
**A1 What the corpus defines** (MEASURED, 12 eval clips of `E:/Projects/TanitAD-artifacts/sfresh_inputs/cache/eval/clips`, probe in this session):
* The trainer and `imag_dump.py` feed `st.rollout(1, z0, A, context=ctx)` with `A = wm.scale_actions(act)` = `[a / WM_ACC_SCALE, ch1 / ch1_scale]` (`v8f_mini.py:942-947`, `WM_ACC_SCALE = 2.0` at :201, `CH1_SCALE["yaw"] = 0.4` at :199). `act = [nan_to_num(d["a"]), d["ch1"]]` of the window frames (`v8f_mini_data.py:661`); frame f's action drives the transition f -> f+1 (`WMAux.forward`: `a = scale_actions(act)[:, :-1]`, `v8f_mini.py:~972`).
* `d["a"]` is the cache's `o["a"]` (`v8f_mini_data.py:570`). **It equals the FORWARD difference of the cache-step speed, a(f) = (v(f+1) - v(f)) / 0.2 s: max |cache a - forward difference of cache v| = 1.19e-7 over 12 clips; cache `v` equals the native track speed at the even rows (`track[0::2, 3]`): max |diff| = 0.0.**
* `d["ch1"]` in the yaw mode = the native track's one-frame backward yaw difference / 0.1 s at the even rows (`ego_channels_native`, `v8f_mini_data.py:394-401`, via `yaw_kin_from_track` :404-417).
**A2 Two definitions exist inside the pinned tool, and they differ for the acceleration.** When the pinned tool executes a plan, `WindowState._finish` (v8f_t1_eval.py:201-224) writes `d["a"][j+s] = ego_channels_native(track slice)[0::2][s, 1]` = the one-frame (0.1 s) BACKWARD track difference, not the cache's forward difference. MEASURED on 6 of those clips: mean over clips of the median |cache a - backward track difference| = 0.11 m/s2 (central 0.4 s difference 0.056, forward 0.0) (a systematic offset of the two spellings), and on the 16-window smoke the cache and the track channel correlate 0.953 (acc), 1.0 (yaw) (`work/smoke/label/ticks/p45_S.npz`).
* `candidate_actions(..., definition="logged")` (default, `--action-def logged`): **a(j+s) = (v_c(j+s+1) - v_c(j+s)) / 0.2 with v_c the track speed of the candidate's executed-form track** (v(j) = the measured track speed, v(j+1..j+10) from the pinned tool's own `hermite_frames`, called not copied, in `candidate_track_rows` = `WindowState.commit_plan` v8f_t1_eval.py:181-193 without writing); ch1 = the backward yaw difference of the same track. All ten actions (frames j .. j+9) therefore come from the candidate (frame j's forward difference needs the first step).
* `definition="executed"` (`--action-def executed`): exactly what the pinned tool writes into `d["a"], d["ch1"]` when it executes the plan; frame j is the measured one. Test: bit for bit equal to the values written by a real `commit_plan` (`test_actions_of_a_candidate_equal_what_the_pinned_commit_writes_bit_for_bit`); the logged form is checked against the forward difference of the `d["v"]` that same commit writes (1e-3 tolerance, float32).
* Why the default is `logged`: the world model was trained on the cache's forward `a`; the executed spelling is about 0.11 m/s2 off it on the median (6 clips). Which spelling the card means is the lead's call; both are one flag, and both go through the same rule.
**A3 Plumbing smoke of control p4 on REAL windows (MEASURED, 16 windows of checkpoint P_s0, `work/smoke/label2/ticks/p45_S.npz`; not the card's measurement, which needs the full window set):** the logged future path as the plan with c = 1.0, definition logged, against the corpus' logged actions of the same windows: corr acc **0.982**, corr yaw 0.9956, median |diff| acc **0.040 m/s2**, yaw 0.0019 rad/s. **The card bar (corr at least 0.99 on each channel) is missed on the acceleration channel at n = 16**; the median bar (0.1) holds. Planted exact profiles are recovered exactly (straight: 0.0; curved w = 0.15 rad/s: |da| 0.0088 (logged) / 0.026 (executed), |dw| 0.0023). The lead must measure p4 on the full set before any run (`--p45-log`, `imag_plan.p4_stats`); if corr stays under 0.99, the card's own bar says nothing is named.

## B. What the card leaves open
**B1 Candidate c = 1.0 is not the plan when the plan brakes harder than B_MAX (finding, same family as DISTRULE E3b).** `a_c = max(c a_P, a_B)` with c = 1.0 is above `a_P` on every step where `a_B(i) > a_P(i)`: plan step 1 shorter than `a_B(1) = 0.2 v0 - 0.12 m`. MEASURED in the test `test_the_card_floor_lifts...` (a 9 m/s2 braking plan changes under c = 1.0, n_lift > 0). The card form is the default (`--floor card`, logged per tick as `n_lift`); `--floor cap-only` = `min(a_P, max(c a_P, a_B))` never goes above the plan and makes c = 1.0 the plan itself bit for bit. Reading arms with `cap-only` needs a card amendment by the lead.
**B2 Control p1 as written cannot hold for {1.0} alone.** "None safe -> c = 0.0" (card) applies to the set {1.0} too: on a tick where the plan itself is unsafe the executed plan is the braking plan, so the dump differs from `off`. The identity probe is therefore `--cand-set 1.0 --fallback none` (nothing safe -> the plan unchanged; default `--fallback zero` is the card) with `--floor cap-only` (B1). Both literal readings are tested: {1.0} + fallback none + both floors returns the SAME plan object (no lift on constant-speed plans), and the default set at a real gap changes plans.
**B3 "a source that returns a gap of 100 m everywhere".** The gate of the card (gap <= 60 m) would make a 100 m source inactive on every tick, i.e. an identity that never exercises the rule. `--const-gap M` replaces every forecast gap at both horizons and every candidate by M AFTER the gate (the head still decides presence and the 60 m gate), so the whole path (candidates, rollout, check, selection, plan replacement) runs; M = 100 with `--floor cap-only` returns c = 1.0 on every active tick and the dump of `off` (CLI test with M = 1e9, because the tiny test model plans at hundreds of m/s). With real plans (< 40 m/s: 1.2 v < 48 m) M = 100 is safe on every tick.
**B4 Gate** = exactly that of the head source of the rule (DISTRULE E4): presence >= 0.5 and `frame_ok` on the five end frames, `g_src <= 60`, finite `g_src, c_src, v_l, g0, v_L, v0`; the same set for `cand-cv` and `cand-imag` (control p7, tested: `active` arrays equal). `cand-label`: the label rule of E4 (`LabelSource`). The tick-state arithmetic is the code of `RulePlanner.__call__` (v8f_t1_eval_rule.py:189-213); test `test_e2e_the_tick_state_equals...` asserts all logged values (g_src, c_src, v_l, v_L, a_l, a_m, g0, active, present, v0, p_src) equal those of `RulePlanner` on the same ticks, bit for bit. A negative `g_src` is active and every candidate is unsafe (c = 0.0, full braking), as the existing rule.
**B5 cand-imag**: `z0` = `wm.z1(adapter(feats[:, -1]) + pos)` of the tick frame (the formula of `head_values`; per frame, so independent of the window length); `st.rollout(1, z0, A, context=predictor context)` for 10 steps; `head_phys` on rolled steps 1..5 (1.0 s) and 6..10 (2.0 s), the gap in metres is used; gap_c(h) = imagined gap + `--imag-shift-m` + (a_l(k) - a_m(k)). The imagined PRESENCE at the horizons is not used (the card gates on the present read only). A non-finite imagined gap makes that candidate unsafe and is counted per tick (`n_nonfinite`).
**B6 Safety**: `v_c(h)` = candidate step speed at knot 5 and knot 10, `(a_c(i) - a_c(i-1))/0.2`; both horizons must hold; `cand-cv` uses `v_L = max(0, v_l + c_src)` and `g0 = g_src + a_l - a_m` as DISTRULE E2; `gap_c(h) = g0 + v_L h - a_c(h)` (hand-checked in a test: 26.5 / 21.5 m).
**B7 Candidate 0.0** is added to the evaluated set when absent (fallback zero), so the fallback is the real braking candidate; the log carries `cand_set` (the effective set) beside `cand_set_arg`.
**B8 Control p3 (noise)**: the DISTRULE wrapper had no noise option (its r4 was a test fixture). `--noise-after-tick SEED` replaces every stored camera token after each window's last tick frame (`t0 + 30 - m`) by noise (the form of that r4). The tool reads only the tick batch (frames <= j) and the plan, so a future-frame read is impossible by construction; the test shows the noise is there (tokens before the last tick untouched, after it changed), the outputs equal bit for bit, and a firing control (noise INTO read frames) changes the imagined gaps.
**B9 Control p5**: `--p45-log` rolls every window at tick 0 under the corpus' logged actions (frames t0 .. t0+9 of the cache) and records the imagined gap at 1.0 s and 2.0 s (`imag_gap_logged`). Test: equals an independent roll of the same states (1e-4 m, CPU, the tiny model). Against the banked `imag_dump.py` read the equality depends on the states: the banked read uses the float16 state file, this tool recomputes z1 from the cache tokens in float32; the card allows "a twice-run compare, stated" if 1e-4 fails.
**B10 Control p6**: `--imag-shift-m X` adds X to every imagined gap (not to the raw read, which stays in the log as `imag_raw`); refused for the other sources. Control p7: 2,399 windows, 3 ticks per window (m = 10, 30 steps); each (window, tick) is rolled once for all candidates in one batch.
**B11 Log** (`--imag-log`): `ci t0 j k tick active present src_bad g_src c_src p_src v0 v_l v_L a_l a_m g0 chosen_idx chosen_c any_safe n_lift n_nonfinite changed` and per candidate `safe gap_h v_h a_h imag_raw` ([rows, C(, 2)]), scalars `mode D TAU B_MAX cand_set cand_set_arg knot_h floor fallback action_def const_gap imag_shift_m noise_after_tick pinned_sha256 imag_plan_sha256 wrapper_sha256 dist_rule_sha256 imag_dump_sha256 rule_wrapper_sha256 join_sha256 ckpt argv`.
**B12 What the card cannot hold as written (for the lead's note before data)**: (a) p1 with {1.0} alone (B2) and c = 1.0 = the plan (B1); (b) "the same definition as the logged actions" has two spellings in the pinned tool (A2); (c) p4's 0.99 correlation is missed on 16 real windows on the acceleration channel (A3); (d) "a source that returns 100 m" and the 60 m gate (B3).
