## Flag A: `--w-rule-own W` (default 0.0)

* **Which output.** `out["traj30"]`. It is emitted at `tanitad/models/v8f_mini.py:1217` (`traj60, subsample_02(traj60), p30`), it is the only trajectory output that the loss trains against `batch["gt"]` (`v8f_mini.py:1320` ade / fde, `:1321` acc, `:1325` launch_along; `traj60` has no term of its own), and it is the plan that the T1-kin tool rolls out (`stack/scripts/v8f_t1_eval.py:294`, `return out["traj30"]`; `:290` keeps `traj30_o` only as `aux`). With the HACC post-map set (`v8f_mini.py:1241`) the tool would read the mapped plan; the loss and this term read the raw plan, as the trainer does for every term (`v8f_mini.py:1237`); no arm of the card sets the post-map.
* **Mask and inputs: identical to `--rule-relabel`.** `rule_own.own_inputs` (`rule_own.py:55`): label presence 1, finite gap and closing label (`D.lead_sup_label_arrays`), `gt_ok`, `frame_ok[:, -1]`, finite RAW `p10f[t][0]` and `v[t]` (read through `RuleRelabel.raw_speeds`, the batch tensors carry NaN as 0); `v0 = p10f[t][0]`, `v_L = max(0, v[t] + closing)`, `g0 = gap`. A sample with a non-finite raw speed is left out and not counted. Check o2 (a) recomputes the mask from the raw arrays and equals it (49 of 64 rows on the synthetic world), and the mask equals `RuleRelabel.stage(...)["mask"]` (test `test_mask_and_inputs_equal_the_relabel_mask`).
* **Cap.** `rule_own.cap_of_plan` (`rule_own.py:67`) = `dist_rule.distance_rule(plan, v0, ones, gap, gap, v_L, m=10, floor_lifts=False).plan` with `plan = traj30[mask].detach().double()` and the rule inputs in float64; the cap is cast back to the prediction dtype and device. Nothing flows through the rule: the cap is a constant tensor. `m = 10` only feeds a log of `distance_rule` (`RULE_M = RRL.RULE_M`).
* **Term.** `rule_own.own_term` (`rule_own.py:74`): per sample `mean over the 30 knots of (x - cap_x)^2 + (y - cap_y)^2` (m^2), batch term = mean over the masked samples; no masked sample returns a plain zero tensor with no graph (exactly 0.0, requires_grad False). `n_active` = samples whose per-sample term is above 0. A plan that already keeps the rule equals its cap bit for bit (the rule returns the original knots for unchanged steps, `dist_rule.py` "keep"), so term and gradient are exactly 0 there; the term never moves a plan ahead (cap-only).
* **Where it enters the loss.** `rule_own.add_own_term` (`rule_own.py:124`, the add line at `:128`): `T["total"] = T["total"] + W * term`. No key is put into `T` (the logged terms keep their key set). The loop calls it at `v8f_mini_train.py:3348`, right after `T = out["terms"]` and before the non-finite check, in the `enc is None` branch (LoRA is refused). The mask inputs come from `RO.stage(b)` at `:3280`, taken before the ego / DAgger stages like the relabel stage (`:3277`).
* **Gate (G-DVB, G-LIVE, selfcheck).** `FLAG_CHECKS["w_rule_own"] = "data:rule_own"` (`:126`); `bad_rule_own` (`:1174`) reads the BUILT record `info["rule_own"]` (built weight, label rows, rule file sha256): declared != built, declared > 0 with no stage, 0 with a stage, negative or non-finite, and the combinations with `--ego-perturb-p`, `--dagger-p`, `--recover-p`, `--encoder lora` are refused (the same refusals as `--rule-relabel`; combination with `--rule-relabel on` is allowed). The record is built at `:2983-2988`. `rule_own_probe` (`:2912`) runs on the real probe batch with a copy of the built model: count `n_lead > 0` (else refusal), `term` finite and >= 0, `n_active`, the gradient norms of `W x term` and of the trajectory loss `w_traj x (ade / 3 + 0.5 fde / 6)` on `traj30`, the add helper moves the total by `W x term`, when `n_active > 0` the term's gradient on `traj30` is above 0, controls: the same call twice and an all-False mask read exactly 0.0. A refusal is `ZZDVB-REFUSEDZZ rule-own`. Selfcheck strings: `levers.w_rule_own=<W>` (gate_extra reads whole floats as ints: 1.0 reads `levers.w_rule_own=1`, 4.0 reads `levers.w_rule_own=4`), also `levers.rule_own_rule`, `info.rule_own`, `rule_own_probe` (only when on). * **Train log, summary, checkpoint (only when on).** log keys per log interval `rule_own_term` (mean of the per-step terms), `rule_own_n_lead`, `rule_own_n_active` (sums) (`:3399-3401`); `summary.json`: `w_rule_own`, `rule_own_n_lead`, `rule_own_n_active`, `rule_own_rows`, `rule_own_term_mean` (`:3439`); the checkpoint carries `rule_own_totals` as a top-level key (not in `cfg`).

## Flag B: `--rule-relabel-weight W` (default 1.0)

* **Samples.** Those whose target the relabel CHANGED: `rr_i["changed"]` of `RuleRelabel.stage` (`rule_relabel.py` `relabel_gt`), taken as `ROW.changed_vector` (`rule_own.py:118`). Not all lead samples: a lead sample whose logged driver already kept the rule is not weighted.
* **How the weight enters each term.** As an EXTRA loss added in the trainer, `rule_own.weight_extra` (`rule_own.py:94`) = `(W - 1) x` the same terms restricted to the changed samples, with the same denominators and the same total weights as `V8FMini.loss` (`v8f_mini.py:1386` `w_traj x (ade / 3 + 0.5 fde / 6)`):
  * ade and fde (`traj_terms`, `v8f_mini.py:551`): per-sample mean / last-knot L2 distance (same `1e-9` smoothing) x GT-valid mask x `(W - 1) x changed`, divided by the GT-valid count; enters as `w_traj x (ade_x / 3 + 0.5 fde_x / 6)`;
  * acc (`accel_term`, `v8f_mini.py:565`): only when `w_acc > 0` (arm G: 0.0), same restriction, enters as `w_acc x acc_x`;
  * launch_along (`launch_along_term`, `v8f_mini.py:590`): only when `launch_intent_w > 0` (arm G: 0.0), same restriction, enters as `w_traj x launch_intent_w x launch_x / 3`.
  The target is `b["gt"]`, the relabelled array the loss receives.
* **No renormalisation.** The denominator stays the GT-valid count, so a weight of 4 means a changed sample counts four times (the loss has its share once plus the extra three). Check w2 compares the extra with a per-sample hand computation (relative difference 3.8e-7) and with `(ade_w - ade_all)` form.
* **Where it enters the loss.** `rule_own.add_weight_extra` (`rule_own.py:133`, add line `:135`), called at `v8f_mini_train.py:3354` after the term of flag A. Guard `ZZRULE-WEIGHT-NOT-APPLIEDZZ` (`:3356`): the total object is unchanged while changed samples exist. The pieces not weighted: the penalty hinges (they read `lab` / `s_h`, not `batch["gt"]`), the S and T terms, the world-model terms (the card leaves them unchanged).
* **Gate.** `FLAG_CHECKS["rule_relabel_weight"] = "data:rule_relabel_weight"` (`:127`); `bad_rule_own` (second half, `:1201-1211`): a weight != 1 needs `--rule-relabel on`, equals the built `info["rule_relabel_weight"]["w"]` (record at `:2989`, with the loss terms it covers and `renormalised: false`), is finite and >= 0, and a weight 1 with a stage built is refused. Selfcheck string `levers.rule_relabel_weight=<W>` (4 reads `4`), only when != 1. Train log key `rule_relabel_weighted_n` (count of weighted samples per log interval, `:3402`) only when != 1; summary keys `rule_relabel_weight`, `rule_relabel_weighted_n`; checkpoint top-level key `rule_relabel_weight_totals`.

## Limits and open points (for the lead)

* The term is in m^2 and added at weight W on a loss whose position terms are in m divided by 3 and 6. On the tiny synthetic world the term reads ~300 to 600 at W 1 (an untrained plan against a lead 8 m away), far above the ade terms. On real data the G-LIVE probe prints `term`, `n_lead`, `n_active`, `grad_norm_term_on_traj30` and `grad_norm_traj_loss_on_traj30` on the first selfcheck; read them before the arms start. The card fixes the form, so it was built as written.
* The rule applied twice equals once: max abs difference 0.0 on the float64 path the term uses (bar 1e-5, met); for the record the same check with the rule called on float32 plans reads 6.1e-5 (rounding amplified by the rule recursion). `checks/o2_o3.json` `o2.b`.
* The mask includes `gt_ok` (as the relabel does) although the term does not read the logged target; a sample without a GT future is therefore left out, as the card says ("the mask ... of `--rule-relabel`").
* Real data was not read: nothing ran on a real cache, the pod or box 2.
