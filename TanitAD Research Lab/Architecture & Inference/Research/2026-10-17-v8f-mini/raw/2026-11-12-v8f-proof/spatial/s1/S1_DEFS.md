# S1_DEFS (PREREG_V8F_PROOF_ADD12, note N8, state-file mode). What the note leaves open, fixed before any trained state is read.
Tier T0: a world-model diagnostic, never driving performance. CPU only. Code: `s1_read.py` (this folder); it imports `spatial/s0e/s0e_read.py` (load_train, load_join, drop_nonfinite_kin, assemble, sub_rows, merge_oof, single_r2c, single_auc_c, paired_auc_c, sha256_file, peak_ram_gb) and through it `spatial/s0/s0_read.py` (fit_probe, paired, permute_within_fold, mean_token) and `spatial/s0c/s0c_read.py` (arm_features, arm_oof_fold, skill, single_skill, paired_skill), and `res/resprobe.py`. Rules E1 to E18 of `S0E_DEFS.md` apply wherever this file is silent (labels E2/E3, probe subsample E4, folds E5, ego E7, pairs E9, bootstrap E11). None of those files is edited.

S1 The state. The rows of `Z` as given, cast to float32. No per-fold fitting, no whitening, no centring, no projection by this tool. The only scaling is the probe's own (`fit_probe`: centring and one global scale on the training rows of the fold) and, in the change read, the stage-0c rescaling of the ego block by the state's spread (`arm_features`).
S2 Rows. The probe set is loaded as stage 0e loads it (shards checked by sha256, labels from the join). Rows with a non-finite kinematic value are dropped (counted, as in `drop_nonfinite_kin`); the same rows are dropped from `Z`. Alignment (t1) is checked BEFORE the drop, on the full row order.
S3 t1 alignment, exact: the `clips` list, `clip_idx`, `t` and the row count of the state file equal the probe set's; `Z` is two-dimensional and finite.
S4 t4 declaration: `--expect-dim` (128 for HIER, 640 for G and W) and `--expect-state` (mean or grid) are required. They must equal the array width, the record's `D`, and the record's `wm_state`; grid implies 640; the record's counts equal the state file's (and, for the full set, split train, lo 600, hi 1800); the sha256 of the state file equals the record's `out_sha256`. `--ckpt-sha256` (the sha256 of the arm's `ckpt_last.pt`, taken by the lead from the arm) must equal the record's `ckpt_sha256`; if it is not given the verdict prints "NOT CHECKED" for that item and t4 can still pass: the lead decides whether to give it. The gate token `wm_state=grid built` of the note is the arm's own record; the tool reads the state mode from the extraction record.
S5 Reads, per fold (folds E5, subsample E4): r-a = lead gap R2 (pooled over the five out-of-fold predictions, finite-gap rows) and presence AUROC (all rows) from the state and from the ego vector (z-scored on the training rows of the fold), the same `fit_probe` calls as `ra_fold`; the difference state minus ego for both, paired on one bootstrap draw.
S6 Change read, arms by `arm_features` on pairs of stage 0d (PAIR_RULE continuous): H = state at g and at g-5 (as the pair `[S_g, S_g - S_{g-5}]`, the same form stage 0c uses) plus the ego block; N = state at g plus the ego block; E = the ego block (v, a, yaw_rate at g, g-5, g+10, z-scored on the training pairs). Skill over persistence. Contrasts H minus E and H minus N, paired on the same draw.
S7 Bootstrap: `RP.boot_counts(n_clips, B 2000, seed 0)`, one draw for every number and difference of a run; the same draw in `pair`.
S8 t3: labels permuted within fold (gap seed 1, presence seed 2, d seed 1, folds as E5) and every fit repeated through the same code; r-a gap R2 of the state and of the ego vector, and the skill of H, N, E, each at or below 0.02. The presence AUROC is printed beside, not barred.
S9 t2 identity of the two code paths: the 64-number mean over the 40 projected cells (`S0.mean_token` of the probe tokens, raw, no rotation) is fed as the state through the same functions as a state file (r-a only); pooled gap R2 and presence AUROC must be within 0.005 of the stage 0e mean-state values. Those two values (`main.r_a.estimates["gap|m"].r2` and `["pres|m"].auc`) and the `controls_pass` flag are read from `RESULT_S0E.json` at run time; no value is written into any file of this folder. If the file is absent, or its controls did not pass, t2 fails with that reason. The t2 values (not the comparison) are cached in `cache/t2_<key>.json`, key = sha256 of `s0e_read.py`, of `INDEX.json` and of `s1_read.py`, so the control runs once for all state files.
S10 Control order and exit: t1 and t4 first (cheap; if either fails nothing else is computed). Then t2 (cache), then the fits (main and permuted labels), then t3. If any control fails: the numbers are written to `RESULT_S1_<TAG>.json`, the verdict prints "LABEL WITHHELD", exit code 2. Exit 0 only when all four pass.
S11 Label: a single line, "baseline (trained mean state), <TAG>" when the declared state is mean with width 128, else "trained state, <TAG>". No outcome name of the card (S0-LEAD-KEPT, GRID-ADDS, Z-ABOVE-MEAN and the rest) is assigned by this tool.
S12 Reporting. Every number carries n (frames or pairs, and clips), tier T0, the estimator (paired episode-cluster bootstrap, clips as clusters, B 2,000, seed 0), "in-sample for the model (train probe clips)" and "a world-model diagnostic, never driving performance". Four-family line: LONGITUDINAL, LATERAL, TACTICAL not measured by this read; STRATEGIC: PAUSED (PI item 25).
S13 Outputs per run: `RESULT_S1_<TAG>.json`, `VERDICT_S1_<TAG>.md`, `OOF_S1_<TAG>.npz` (labels, clip indices and the out-of-fold predictions of the main labels, compressed, for `pair`), `stages/<TAG>/fold<K>.npz` (resumable per fold, signed by row count, pair count, width and the state file's sha256 prefix). `pair --a --b`: `PAIR_S1_<A>_minus_<B>.json/.md`, differences A minus B on gap R2, presence AUROC and the skill of H, N, E, same draw; refused if either run failed a control or the two runs carry different label arrays. `spread --results ...`: `SPREAD_S1_<NAME>.json/.md`, min, max, range and the sample standard deviation (ddof 1) of each point value over the runs (the replicate floor of note section 4; needs at least two runs that passed their controls).
S14 Smoke (`smoke`): the first N clips of the probe set (default 300), whole-clip (gap, presence) tracks swapped between clips before anything is computed (rule E18); it prints shapes, counts, timings, t1 and t4 only and stores only `smoke/RESULT_S1_SMOKE_D<dim>.json`.

## Departures from the note's wording (each a reading choice, not a change of the question)
D1 (S6) The change arm H uses `[S_g, S_g - S_{g-5}]` (the stage-0c form, the same information as "state at g and at g-5"), not the two states concatenated.
D2 (S4) The note's "gate record of the arm shows wm_state=grid" is read from the extraction record (`wm_state` written by `extract_states.py` from the checkpoint's config), not from the arm's gate token file, which is not an input of this tool.
D3 (S4) The checkpoint sha256 comparison is against the value the lead passes in `--ckpt-sha256`; without it that one item is not checked.
D4 (S9) The t2 comparison covers r-a only (the note names gap R2 and presence AUROC).
D5 (S2) Dropped rows follow `s0e_read.py`; the state file is aligned before the drop.
D6 (S5) The ego floor is the single `fit_probe` on the 3 ego columns (as E7), and is recomputed per run (cheap) so each run stands alone.

## Named gaps
G1 The eval-bank reads (note section 2, "r-a also on the eval bank frames") are not in this tool: the pod's eval states are not in the probe set's row layout; they need their own alignment file. G2 Intervals over clips do not carry training variance (H-ESTIM-SEED-1): use `spread`. G3 Linear and kernel reads of a trained state: a negative is about this read. G4 One checkpoint per seed (the last step).
