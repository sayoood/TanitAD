## D. Numbered reading choices (each moves no threshold, bar or outcome rule)
* RG1. Q1 and Q2 per seed, then both seeds: the card needs both seeds. When the two seeds give the same name, that is the name; when they differ, the pair reads Z-FLAT (Q1), and for pixels the baseline rule R10 (any seed without positive headroom: NO-HEADROOM; both seeds the same label: that label; else IMAGINE-FLAT). Per-seed names are always printed.
* RG2. The 0.90 bar is read on the point estimate: held-out skill of the arm divided by the held-out skill of the token grid (baseline decoder, same frames and folds). A paired bootstrap interval of the ratio is printed, not used.
* RG3. Decoder by state layout: G arm = the baseline grid decoder (1x1 conv from the 16 channels of each cell on the 4x10 grid, cell-major flatten undone, cell = r x 10 + c as the cache's row-major token order); W arm = the baseline vector decoder (Linear 640 to 256x4x10). Both keep the baseline trunk, standardisation (per dimension or per channel from training rows) and training recipe. Only the input layer and the two buffers change (tested: at width 128 the state-dict shapes equal the baseline's).
* RG4. "G minus HIER" = arm skill minus the HIER skill of the same seed number (baseline source Zs0 or Zs1, 128-wide mean state). Computed from the baseline stage files, PAIRED (same frames, folds, episodes, same bootstrap draws; frame identity of the stage files is checked through the per-frame mean-image error, relative difference below 1e-4). If those files are absent or not frame-identical, the line reads "side by side" with the RESULT_LATVIS.json values and no interval; Z-ABOVE-MEAN then cannot be reached and the verdict says so.
* RG5. Q2 in pixels: the learned rollout (HJEPAStack.rollout, context 1, composed 0.2 s steps, as R9) at 2.0 s, headroom and a minus b exactly as R10; the stacked predictor is also labelled (the card names the learned rollout). The r-b lead-gap reads (IMAGINE-LEAD, IMAGINE-EGO) and Q3 are not part of this read; the per-window latents for r-b are saved (section F).
* RG6. Control c4: participation ratio = (sum of eigenvalues)^2 / sum of squared eigenvalues of the covariance of the arm's raw level-1 state over the pool frames (windows of eval-141). Below 32 flags the grid arm (the card flags G); the names of an arm type with a flagged seed read NOT-QUOTED. W (mean) is reported only.
* RG7. Attribution (card: LOCATION only if G differs from W in the same direction, WIDTH if W equals G): per seed, paired G-W difference on skill (frames) and on (a - b) at 2.0 s (windows), same draws. LOCATION if the interval excludes 0 in the direction of the effect at both seeds, WIDTH if it includes 0 at both seeds, else MIXED; NO-EFFECT-TO-ATTRIBUTE if G's own name is Z-FLAT (Q1) or not IMAGINE-PIXELS (Q2). Needs G and W at both seeds, else NOT-READ.
* RG8. An arm whose checkpoint or sha256 file is missing or mismatched is skipped and named in the job log; an arm type missing a seed reads NOT-READ.
* RG9. v1 and v3 are checked per arm; a miss gives exit code 2 with the results written (as the baseline). v2 headroom missing reads NO-HEADROOM, not a stop.
* RG10. Decoder seeds, folds and the inner split are the baseline's (seed = fold index); the same decoder recipe is therefore applied per arm; no replicate of the training run exists (one checkpoint per arm and seed, as the card).

## F. Per-window latents for the lead-gap read (saved, no lead-gap number computed)
`latvis_gw/LATENTS_GW_<ARM>.npz` (float16 states) with keys: `z0` (start state of each used window, [n, 640]), `pred_2s` (learned rollout at k = 10, 2.0 s, the array the pixel read decodes), `true_2s` (true state at +2.0 s), `pred_0p8s`, `true_0p8s` (k = 4), `eid` (episode id), `g0` (grid step of the window start), `t` (= g0 + 15), `w_fold` (decoder fold of each window), `act_scaled` ([n, 15, 2], WM-scaled actions of the window). Beside it `LATENTS_GW_<ARM>.npz.json`: checkpoint sha256, state kind, width, n_windows, n_episodes, sha256 of the file and of every array. Window order is the used-window order of the context (same as `RESULT_LATVIS_GW.json` counts; windows_used). Smoke copies (12 episodes, 169 windows) are under `smoke/`.

Results: `RESULT_LATVIS_GW.json`, `VERDICT_LATVIS_GW.md`, `panel/`, `LATENTS_GW_*`, `LATVIS_GW_DONE.txt` or `LATVIS_GW_STOP.txt`, `latvis_gw_job.log`. The job can be restarted: frames, collected latents and finished stage files are skipped (a stage file made from another checkpoint refuses).
Known ways the real run can fail: the shared GPU lock held for hours (the driver waits up to 6 h); F: or commit memory low; the frame identity check failing (stops before the GPU); `E:` artefact files (`sfresh_inputs/cache/eval`, `latents.pt`) not reachable.
