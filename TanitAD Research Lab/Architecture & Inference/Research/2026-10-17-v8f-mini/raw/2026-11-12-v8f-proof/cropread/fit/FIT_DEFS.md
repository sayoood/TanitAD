## 0. FIRST: clauses of the card that can fail by construction, and what the code cannot do as written

1. **The PASS bar has a ceiling that the pilot cannot exceed: the tool's own label-gap slope.** The name reads r of the RG10 slope (run of at most 10 frames, found from the reader's gap) against the label closing speed, which is a slope over at most 5 frames (`closeread_dump.py` label_clip, RUN_MAX 5; `kinclose4.py:83-101` run_index, `:104-118` run_slope). Even the label gap itself read as a gap does not give r = 1: that is the tool's arm RL10 (`kinclose4.py:236-268`, key `RL10`). If RL10's lower end of r in `GAPRANGE_RESULT.json` (arm ALL) is below 0.9, `CROPREAD-PILOT-PASS` cannot happen for any gap. **The lead reads `arms.ALL.RL10.r_ci` before the fits** (I did not open it). The selftest shows the opposite case on a synthetic world (the label gap read gives PASS).
2. **c3, level 0.25 m, can fail by construction on the same ceiling and on short runs.** A white error of 0.25 m gives a slope error of sd 0.25 / sqrt(sum (t - tbar)^2) = 0.138 m/s over a full 10-frame run (dt 0.2 s), 0.395 m/s over a 5-frame run and 0.88 m/s over a 3-frame run (the run rule stops at a label step above 3 m, `kinclose4.py:97`). REACHES needs the lower end of r at or above 0.9, so it holds only if the label closing speed has an sd of about 0.4 m/s or more over the frames, and RL10's r is at or above about 0.9 (point 1). Level 8 m (BELOW) is safe: slope sd of 4.4 m/s. I built the planted dump as label gap plus noise on the frames with a label and `GAP_FILL_M` = 1000 m on the others (a step the run rule stops at); this is my choice, the card names none (`read_cropread.py` planted_dump). With the planted dump on the frames with no label left at the reader's own gap, runs would cross into garbage at track starts.
3. **A constant estimate**: `closeread_fit.pearson_sums` (`closeread_fit.py:228-231`) returns NaN when the variance is 0, the bootstrap interval of r is NaN (np.nanpercentile of an all-NaN slice, a RuntimeWarning), and `kinclose4.r_name` (`:275-282`) turns a non-finite interval into `-NOT-DECIDED`. So a constant gap reads NOT-DECIDED, never REACHES, never BELOW (selftest: "a constant gap reads NOT-DECIDED"). A float-noise-level non-constant head reads a noise-level r, below the bar. No crash and no false name.
4. **c5**: the sd clause reads `sd(gap error) >= 0.8 * sd(label gap)` on the frames of arm ALL (`kinclose4.meas`). A head that outputs a constant has error sd = label sd (ratio 1.0), so it passes; the clause fails only for a permuted head whose output correlates POSITIVELY with the label on the evaluation frames (error variance = var(out) + var(L) - 2 cov). In my synthetic test the permuted fit read a held-out R squared below 0.3 (and once an anti-correlation of -0.99 on three held-out clips: the correlation of a permuted fit is not 0, only its R squared is bounded, which is why the clause reads error sd and not r). `-NOT-REACHES` is the second half and cannot fail for a permuted fit unless r is at or above 0.9 by chance.
5. **c2 needs the same environment**: B = 2,000, seed 91 (`kinclose4.py:32` BOOT_SEED), the episode map of the original read (`closeread/episode_map.json`), and the file `GAPRANGE_RESULT.json` with sha256[:16] 9965504cfde0dae4. The wrapper checks the hash of the file and the hashes of the two tools (kinclose4 9a734658232bc327, kinclose6 f5be6f8077f6f563, both read from the card and equal the local files). If the push changes a byte of a tool, c2 fails by its hash clause. Numpy RNG streams are version-stable; a differing numpy build is the only residual risk.
6. **c6 text of the card** ("passed and no failed or error"): my check takes the whole pytest output and refuses any word `failed`, `error`, `errors` (case-insensitive). A warnings section that prints the word "error" (a library warning) turns c6 red. Run pytest with `-q` as shown below.
7. **Interface gaps I could not close (assumptions)**: (a) `lists/LISTS_RECORD.json` has no stated field names; c4 accepts the train list's sha256 if ANY 64-hex string in the record equals the sha256 of the file `lists/train_final.txt` (bytes) or of the clip ids joined by line feeds. (b) the card's "written before the first fit" cannot be tested from files; the fit records carry the list sha256 and a finish time, the LISTS_RECORD is not time-compared. (c) `ctl/C1.json`, `C7.json`, `P1.json` are read for the top-level boolean `pass` only (`pass is True`). (d) The numbers "5.68, 6.31 and 1.65 m" of the card are not defined in the card ADD98 file I read (not found); I print root mean square AND sd of each part and the card's three numbers beside them with the words "a different object". (e) `hparams_equal_card` is recorded per fit (true only at 40 epochs, batch 256, lr 1e-3, weight decay 0.05, 1 warm-up epoch); it is shown in c4's detail and does NOT gate c4 (the card names no such control; the lead decides whether to add it).
8. **Card items done by a choice**: MLP activation GELU (the card names none); the learned position vector and the query are initialised N(0, 0.02); one attention layer with 4 heads on width 256; no layer norm after the attention; H5 uses frame f when f >= 4 (the five frames exist in the clip; the four earlier frames need no valid gap); the warm-up is linear per step over the first epoch, then cosine to 0 per step; the epoch kept is the first with the lowest mean smooth L1 on the sel clips' valid frames (the sel loss uses the same samples rule as training); for the permuted fit the labels of the fit frames and of the sel frames are permuted separately (fixed seeds 9900 + seed, 10900 + seed), so selection cannot see the true labels.

## 2. Definitions with sources

* Dump format (fields): from `closeread/closeread_dump.py:dump_split` (the dict built from `cols`) and `closeread_fit.py:31` DUMP_KEYS. Copied from the present reader's dump of seed index K: `cid, clip_index, frame, lab_present, lab_gap, lab_closing, lab_run, clips, dt_s`. Replaced: `gap` (the head's output, metres, float64; NaN where H5 has no five frames), `p` = 1.0, `clos` = 0.0, `valid` = present `valid` AND `isfinite(gap)` (so the scored rows of card ADD81 are the same rows: `closeread_fit.build_rows:86-96` needs 25 consecutive valid rows), `seed` = K. The card says "every other field copied"; `valid` is copied and narrowed by the head's own NaN only.
* Estimator: `kinclose4.make_ctx` (`:40`) and `kinclose4.measure` (`:236`) unchanged, called by `read_cropread.load_ctxs` / `measure_dumps`; the per-form name by `kinclose4.r_name` (`:275`, REQ_R 0.9 at `:31`). The card's name from D-H5: PASS if `r_name` gives REACHES (lower end >= 0.9), FAIL if BELOW (upper end < 0.9), else NOT-DECIDED. Per form: `CROPREAD-<arm>-<head>-REACHES|BELOW|NOT-DECIDED`.
* Cut (`read_cropread.cut_ratio`): on D-H5 (B-H5 as `CROPREAD-BOUND-CUT-BY-2-...`): ratio = sd(pilot gap error) / sd(present reader's gap error) on the frames that the pilot's dump AND the present dump both measure (reader valid, label gap present, scored row), pooled over the two seeds (sd about the pooled mean, as `kinclose4.point_err`); interval: percentile 2.5 / 97.5 of 2,000 draws of evaluation episodes (one draw shared by both seeds and both readers: paired); seed 99. REACHED when the upper end <= 0.5, NOT-REACHED when the lower end > 0.5, else NOT-DECIDED. The sd is about the mean: a constant offset of the pilot does not count in this cut (as in the tool's gap-error sd).
* Printed with no name: gap error by bin (`P.gap_error`: ALL, NEAR below 20 m, MID 20 to 40, FAR above 40; `kinclose4.py:28`); the split of row 154 (`kinclose6.measure` at `:180` on `kinclose6.frame_set` at `:43`; stored as `split_row154`); the three parts of card ADD98 on the pilot's raw gap through `make_part_joins.part_arrays` (`make_part_joins.py:190`) over the dump rows as a pseudo-join (clip = `cid`, row = dump row, a clip's rows are consecutive frames; mix frames: label gap present in 0..60 m, valid, finite gap; no map, no minimum): m = clip offset, s = slow drift (window of 5 mix frames each side in the same run), f = fast part; tested against plain loops and against `make_part_joins.second_parts` (`:241`) with an identity map; the values per fit seed (`r_per_seed`, gap error `per_seed`); the sel loss and kept epoch per fit.
* Controls: c1, c7, p1 from `ctl/*.json`; c2, c3, c5 as in the card on the present reader's dumps, with `GAPRANGE_RESULT.json` for c2; c4 from the lists, `LISTS_RECORD.json` and every `FIT_RECORD.json` (expected: eight fits plus `D_H5_s0_perm`; with p1 failed only the five arm D fits); c6 from the pytest output. `names` refuses unless c1..c7 are all `pass: true` and the file says `controls_all_pass`; p1 only decides whether arm B is opened.
* Fit (card section 5): `crop_fit.make_model`: LayerNorm(1024), Linear to 256, position vector [130, 256], one query, `nn.MultiheadAttention(256, 4)`, token dropout 0.1 (never drops every token), H1 MLP 256-256-1, H5 MLP 1280-256-1 on z of f-4..f, 60 * sigmoid, smooth L1 beta 1 m on frames with `lead_valid == 1`, finite, 0 to 60 m; AdamW 1e-3, weight decay 0.05, batch 256, 40 epochs, one warm-up epoch, cosine to 0. Tokens are memory-mapped per clip (`[n, 2, 65, 1024]` float16, position order window W32 tokens 0..64 then W16 tokens 0..64); one prefetch thread; process memory is the batch only (about 0.35 GB per batch for H5, depth 3), the page cache holds the token files.
