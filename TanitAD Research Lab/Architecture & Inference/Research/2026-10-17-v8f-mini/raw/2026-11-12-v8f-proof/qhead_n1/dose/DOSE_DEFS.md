## What was built (all in qhead_n1/dose/)
* `pod_qhead_dose_inputs.sh` (pod, nohup): slot wait, then the layout (`pod_dose_layout.py`, once), then per checkpoint LSD_s0, LSD_s1 (queue leadsup_b): `extract_states.py --lo 0 --hi 4572` into `/workspace/v8proof/qhead_dose/states/<ARM>_dose_train.npz`, then `pod_lead_apply.py` into `<ARM>_dose_train_lead.npz` (+ `.head.npz`, `.json`). The banked invocations are used unchanged (tools not edited). New names only; an existing record means skip, an existing file without a record means STOP (never overwritten). After each extraction the record must read lo 0, hi 4572, n_clips 4572 and the checkpoint sha256 must equal that of the banked 1,200-clip record. Markers in `qhead_dose/run/`, last line `ZZ QHEAD-DOSE INPUTS DONE <n>` or `... STOP: <reason>`, DRY=1 prints all commands (checked: creates nothing).
* `pod_dose_layout.py` (pod, CPU, one clip in memory): the layout of positions 0..4571: clips, clip_idx, t, kin (v, a, yaw_rate from the cache clip files, as `extract_probe_set.py` reads them), frames. Needed because the label pack carries `v` (ego speed, cache kin[:, 0]) and the cache exists on the pod only.
* `build_dose_pack.py` (dev box, pure numpy): the pack for all 4,572 clips from the layout and the join, same rule as the banked builder (pres = lead_valid == 1; gap = lead_gap where valid, finite, 0 <= gap <= 60 m; v = kin[:, 0]). Refuses a clip absent from the join, a join frame count different from the layout, rows not clip by clip, an existing output; `--states` checks clips, clip_idx and t of a state file against the layout. Where it runs: the dev box (the join is there; the pod may not hold it: `find /workspace -name join_train.npz` if the lead prefers the pod). Data it needs: the layout file (about 10 MB, pulled from the pod), the join. The pack (about 20 MB) goes to the pod as `/workspace/v8proof/qhead_dose/pack/train_pack_all.npz`.
* `dose_d1_pack_check.py` (dev box): control d1, rows matched by key (clip, frame): missing rows, extra rows, clip names, gap/pres/v (NaN pattern and largest absolute difference, bar exactly 0.0), join sha256 equal. Exit 0 / 2, JSON.
* `dose_d2_state_check.py` (pod, numpy only): control d2: records (checkpoint sha256 equal, new record lo 0 and n_clips equal to its clip list), structure (clips[600:1800], one contiguous run of rows, clip_idx - 600 and t equal row by row), values (largest absolute difference of the float16 states <= 1e-4 x rms of the banked state), planted shift by one clip (compared by position; it MUST exceed the bar, else the control fails as blind; JSON field `planted_shift.fails`), optional `--layout` (clips, clip_idx, t of the new file equal the layout the pack was built from). The array Z is streamed in chunks of 8,192 rows from the npz member (stored, not compressed), small arrays are loaded whole; MEASURED here on the real `G_s0_train.npz` (121,166 x 640 float16): slice and rms equal a full load.
* `pod_qhead_dose_fits.sh` (pod, CPU): two fits with the unchanged `qhead_fit_n1.py`, `--fit-clips 3048 --select-clips 762 --check-clips 762`, seeds 0 and 1, `--lead` and `--banked-head` of the new lead read, out `qhead_dose/heads`. Refuses unless: sha256 prefixes of `qhead_fit_n1.py` (57e1242713e0b42e, the value of note N2) and `qhead_model.py` (f6ff755e3dd4e212) match, pack present, `controls/d1_pack.json` and `controls/d2_<ARM>.json` contain `"pass": true`. Memory wait: more than 20 GB of the container free before each fit (one probe, poll 60 s, at most 2 h, then STOP). Last line `ZZ QHEAD-DOSE FITS DONE <n> of 2`.
* Tests (6 files, one per tool) and `run_mutations_dose.py` -> `MUTATIONS_DOSE.json`.

## Does qhead_fit_n1.py need a change? No (read from source)
* Sets: `clip_sets` (line 114) takes half-open clip-index ranges from the state file's clip order: fit [0, 3048), select [3048, 3810), check [3810, 4572); the sum must not exceed `n_clips` of the file (line 282-283): 3048 + 762 + 762 = 4572 = n_clips, accepted. These are the sets of note N2 (positions 0..3047, 3048..3809, 3810..4571).
* Pack and states: `build_rows` (line 86) requires the pack's clip list equal to the state file's (names and order, line 93) and matches rows by (clip_idx, t); with a pack built from the layout of the same file this holds; a pack of 1,200 clips would be refused, as intended.
* The record fields `lo`, `hi`, `n_clips` of the state record are only copied into `states_record` (line 338); the tool does not read lo or hi for any decision. `is_eval_path` (qhead_model.py:98) looks at the last two path parts only: none of the new names contains `eval`.
* Memory: Z float16 about 0.6 GB resident; the fit rows are index arrays; the select pass is over about 762 clips each 250 steps. Well inside 20 GB.
* Control d3: the record lists `clip_sets` and `clip_index_range_of_rows_used` (line 332); the existing `h8_check` of the names tool reads them. Not changed here.
So no `qhead_fit_n1b.py` was written.

## REVIEW for the lead
1. The dev-box `extract_states.py` is CPU only (`CUDA_VISIBLE_DEVICES` default -1, `torch.set_num_threads(1)`, no device argument). The 57 s "on the GPU" of the lead does not come from this file. Compare `sha256sum` of the pod copy with the dev copy before the run. If the pod copy differs and takes arguments, pass them with `QD_EXTRACT_ARGS` (appended after `--out`). With this copy, 4,572 clips on one CPU thread may take much longer than 4 minutes (not measured).
2. Slot wait is also placed before the layout step and the lead read (both CPU) for simplicity; they wait for the same condition.
3. The lead read (`pod_lead_apply.py`) builds its history index with a python loop over rows (461,518 x 5); expect a minute or two, not measured.
4. d1 compares `v` too: the new `v` for positions 600..1799 comes from the cache clip files by `pod_dose_layout.py`, the banked `v` from the probe shards (same cache, same field `v`). The control d1 would read a difference if they were not the same field. KIN_REF (s0e E15) was never supplied, so v against the cache values was not checked before either.
5. A row with a non-finite `v` outside the 1,200 clips is kept (the banked builder asserted none): the count is `meta.n_v_nonfinite_rows`; the fit does not read `v`.
6. d2 runs on the pod (banked states are there); d1 on the dev box. The lead copies `d1_pack.json` to `qhead_dose/controls/` before the fits; the fits script reads both.
7. Head files are named `LSD_s0.qhead.npz` in `qhead_dose/heads` (arm label of the fit); the later rollout arm names (`LSDQF_s0`, `-QF`) and the adaptation of the rollout queue and the names tool are not built here.
8. File names of the new states carry `_dose_`; the banked `<ARM>_train*.npz` stay untouched (the tests assert it on the stub pod).
