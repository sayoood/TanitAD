## Fit (qhead_fit_n1.py), decisions
* Sets: `clip_sets` (line 114) gives half-open ranges fit [0,800) select [800,1000) check [1000,1200) of the state-file clip index (manifest order; the pack must share it, line `build_rows`). Refuses fewer clips than the sum (`fewer than`), non-positive sizes, and a set with no usable row. A longer file leaves the later clips unused (recorded as `n_clips_in_file`). Argument names `--fit-clips --select-clips --check-clips --select-every`; `--held-out` of the first run is gone.
* Selection (`fit_head`, line 165; update rule line 206): after step number s completes, for s a multiple of `--select-every` and at the last step, the pinball loss at 0.20 on the select rows (`eval_select`, line 160, metres, output before the shift) is read; strict `<` keeps the earlier step on a tie. The step count in the record is the number of steps done (250, 500, ..., 19164). The cosine schedule still runs to the full `--steps`, so the parameters kept at an early step are those of a head whose rate had not yet decayed (stated, as the note leaves it open).
* Shift (`shift_value` line 216): c = np.quantile(q_head - label, 0.80) on the select rows (linear interpolation); share of select rows with q_head - c above label lies in [0.2 - 0.2/n, 0.2 + 1/n]. `fold_shift` (line 221, call line 306) subtracts c/50 from `mlp.2.bias`, so the saved head outputs q_head - c. The fit reads the saved file back and refuses (SystemExit REFUSED) if the loaded head differs from q_head - c by more than 1e-5 m on any fit, select or check row (line 313; `fold_check_max_abs_m` in the record). Saved npz keys: the six tensors, hist, q_level as in the first run, plus `shift_c_m` and `selected_step` (the unchanged loader ignores them).
* Record (`<ARM>.qhead.json`): keys the unchanged rollout tool reads are kept (`states_record.ckpt_sha256`, `head_file_sha256`). New: `clip_sets`, `n_{fit,select,check}_rows`, `coverage_{fit,select,check}` (share of rows with the USED output above the label), `pinball_{fit,select,check}_m`, `select_curve`, `selected_step`, `shift_c_m`, `h5_check_coverage_in_0.15_0.25`, `files_read_sha256` (training files only; evaluation paths refused as before), `tool_sha256` of fit and model, and `clip_index_range_of_rows_used` (min and max clip index of the rows that actually entered the gradient steps, the selection and the shift; read by control h8).
* Departures from the note: none in the lever. Choices the note leaves open: shift by linear-interpolated quantile; selection value in metres; ties by strict `<`; the first-run gradient check on the first batch is kept.

## h3 in two parts (qhead_h3_n1.py)
(a) bar exactly 0.0 (`== 0.0`, line 71): g_src equals the logged g_used and g_used equals min(g_head, q_head) of the side file, where q_head is the used output (shift inside the saved head). (b) `compare_b` (line 48): g_src against the offline recomputation within `--tol` (default 0.02 m, `TOL_M`); the planted check adds `--planted` (0.10 m) to the recomputed values and the comparison must FAIL; if it does not, `counts` is False (line 92), part (b) PASS is False, and the overall result is FAIL with `why`. Output fields `a_in_rollout`, `b_offline_recompute` (with `planted`, `counts`), overall `PASS`. Also written for the read: beside numbers as in the first run.

## REVIEW for the lead
1. The pod queue of the first run (`pod_qhead_queue.sh`, `qhead_arms.txt`) was not adapted: the arm names, the fit script name and the rollout head files must be changed to `LSQE_*` and `qhead_fit_n1.py`, and the fit needs `qhead_fit_n1.py` plus `qhead_model.py` side by side. Not built here (scope).
2. h6 evidence: `MUTATIONS_QHEAD_N1.json` covers only the n1 fit, h3 and names; the first-run `MUTATIONS_QHEAD.json` covers the unchanged rule tool. `--h6` takes one file; the lead decides whether to require both.
3. The names read h2 from `rule_log_LSQHI_s0.npz` of the first run (control rollout carried with h1), found under `--rule-log-dir`.
4. m1 shows the record ranges alone would not catch a check row in the selection (the record is written from the masks); the behavioural test (check labels +100 m change nothing) does. The h8 read of the record is therefore necessary and not sufficient; the fit tests carry the weight.
5. float32 fold: `fold_check_max_abs_m` on synthetic data is far below 1e-5; on real heads with outputs near 60 m the float32 rounding of the output is of the order 4e-6 m, closer to the bar. If a real fit refuses on this alone, the bar of the note (1e-5) is what is stated.
6. The tool file for h1 is the one the lead passes; the queue log records a 16-character prefix.
