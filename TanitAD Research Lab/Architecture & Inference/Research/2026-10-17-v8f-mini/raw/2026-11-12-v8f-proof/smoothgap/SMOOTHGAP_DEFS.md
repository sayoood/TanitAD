## Choices (the card is silent)
* Mix frame. A frame is a mix frame when its label gap is valid in the evaluation join (`lead_valid == 1`, finite, `0 <= L <= 60`) and every reader seed that the arm uses has a read of it (dump `valid`, finite raw gap, inside the join's rows of its clip). S50_s and S25_s need the read of reader seed s; E and ES25 need both. A frame with a valid label gap that is absent from a needed dump counts as "no reader read".
* Run. Neighbours are two mix frames of the same clip with join rows r and r + 1 (the clip index is compared as well, since the last row of one clip and the first row of the next are also neighbours in row number). A run ends at a frame that is no mix frame, which includes a frame whose label gap is not valid.
* The map is applied per reader seed (g_s = min(r_s, Q_s(r_s)), the q50 map of that seed), then the mean is taken: P = (g_0 + g_1) / 2. Model seed s of S50 and S25 uses reader seed s; E and ES25 are one join for both model seeds. The second file of such a pair is a byte copy of the first, so the two have one sha256 and the record states `pairs_equal` per arm.
* No limit is applied. P below 0 or above 60 stays in the join and is counted (`n_mixed_below_0`, `n_mixed_above_60`, with `min_mixed` and `max_mixed`). The rule's label source takes a gap as a lead only from 0 to 60 m, so the rule sees no lead on such a frame; the smoothing still runs through it, because the frame is a mix frame. A convex combination of mapped gaps stays inside their range, so P never reaches a magnitude that a join of card ADD96 (arm K100) did not already hold.
* Control p0 is the e0 of card ADD96 computed again for this build (both reader seeds, same facts and bars).
* Control p1 asks: (1) the saved gap equals, within 1e-4 m, the processed gap computed a second time by `second_routine`, a plain loop clip by clip and frame by frame from the dumps and maps, written separately from the build (which works on whole arrays and across runs together); (2) the causality probe: the build function is run again after the mapped gap of the LAST mix frame of every run is raised by 7.0 m (all seeds), and the largest absolute change at every other mix frame has to be exactly 0; the record also holds the change at the changed frames and the probe reads red unless it reaches them (at least a * 7.0, or 7.0 for E; a run of one frame moves by 7.0); (3) frames with a valid label gap and no reader read carry the label gap (`n_label_frames_without_read_not_label_gap` = 0) and are at most 5 percent of the valid label frames, per file; (4) every other field equals the evaluation join (value, dtype, shape) and no frame changed outside the mix frames; (5) map files are `QMAP_LR16_s<s>_q50.json` with a sha256, the dump has a sha256; plus `pairs_equal` for E and ES25 and the same sha256 for both files of a pair, the eight arm names with the right a, seeds and flags, a count (not a bar) of values below 0 and above 60, the dtype of `lead_gap`.
* The saved gap is float32 (the dtype of the join); the build works in float64. The 1e-4 m bar holds for gaps up to 1,638 m in magnitude (half a float32 step), which is wide for a gap read.
* Error statistics of P minus the label gap on the mix frames use the terms of row 154 as in `ERRCUT_DEFS.md` (mean, sd, rms about the clip mean, sd of the clip means, step rms and step sd); `step_rms` is the row 154 form of "change between neighbouring frames".
* The record is bound to the evaluation join by sha256 and to every join file by sha256; the queue admission reads `p0.PASS` and `p1.PASS` and the hashes; the reader recomputes p0 and p1 from the record fields and checks the files on disk.
* Names (card section 3): four per arm (`-CUTS-CONTACT` / `-CONTACT-NOT-SHOWN`, the three-way half-the-gap name with H = half of the point value of C(RR) minus C(RLc), the three-way falling-behind name, and the three-way K100 name on the interval of C(X) - C(K100)) and the name of the card: `-A-PROCESSED-GAP-SUFFICES` when at least one arm is WITHIN-HALF-THE-GAP and is not FALLS-BEHIND-MORE, else `-NO-PROCESSED-GAP-SUFFICES`. `read_smoothgap10k.card_check` derives the card name a second time from the intervals of the payload (not from the other names) and the names stage refuses on a mismatch. There is no ladder name.
* The names stage refuses a controls file unless `controls_all_pass` is true, the six controls p0 to p5 are all present and each reads PASS, and a payload exists; it binds the result by the sha256 of the controls file.
* Control p3: round(C(RR), 4) == 0.0954, round(C(RLc), 4) == 0.0000, round(C(K100), 4) == 0.0477. p5: the engine's grid read ALL_PASS and the strategic grid `stage_A_pass` and `stage_B_pass`; the STRATEGIC pair reads (each arm against RR and RLc) are computed in the controls stage and stored under `strategic`; the other families are under `families`. With p5 failed no strategic reading is written. K100 is registered in `R.ALL_RUNS` as the other label-fed runs are, and the pairs `<ARM>-VS-K100` are in the pairs definition, so C, U and F differences against K100 are in the payload (`differences_against_K100`).
* Queue: root `$GP` = `${GR_ROOT:-/workspace/v8proof/smoothgap10k}`; check folder `${GR_CHECK:-/workspace/v8proof/gaprule10kb/check_j2}` (the passed record of card ADD95; wrapper hash cbf7063d867c9f4e); joins `${GR_JOINS:-$GP/joins}`; small folder `$GP/small_sg`. One process per model seed with markers `START_SMOOTHGAP10K_s<k>.txt`, `SMOOTHGAP10K_DONE_s<k>.txt`, `SMOOTHGAP10K_STOP_s<k>.txt`, log `queue_smoothgap_s<k>.log`; with `GR_SEED=ALL` the done marker is `SMOOTHGAP10K_DONE.txt`. Run folders `$W/t1/I10RLcKF5P30Hb20p<ARM>_s<m>`. The admission checks all eight join files whatever the seed scope, and the banked K100 runs (`T1_DONE`) are required in addition to RR and RLc.
* DRY=1 prints each command; the tests compare each DRY command with the model queue's DRY command for the label gap arm after removing the arm suffix and the join path.
* Not built: `lead_pytest.out` (the run of the tests that the lead makes on the dev box, control p4); the pod copies of the dump, map and join files.

## Order of use
1. dev box: `python make_smooth_joins.py --selftest`; `python read_smoothgap10k.py --selftest`; pytest (command in the head of `test_smoothgap.py`, the whole file), output to `smoothgap/lead_pytest.out`; `python make_smoothgap_queue.py` (only to rebuild the queue).
2. pod: `make_smooth_joins.py --eval-join /workspace/v8proof/hierrep/pins/join_eval141.npz --dump-dir /workspace/v8proof/closeread/dump/both --qmap-dir /workspace/v8proof/integ10k/qmap_sweep --out-dir /workspace/v8proof/smoothgap10k/joins` (one run; refuses an existing folder; last line `ZZ SMOOTH-JOINS p0 PASS p1 PASS`).
3. pod: copy the kit to `$GP/kit`; `DRY=1 bash pod_smoothgap10k_queue.sh`; then `GR_SEED=0 bash pod_smoothgap10k_queue.sh` and `GR_SEED=1 ...` (or ALL).
4. pod read: `bash podread_smoothgap10k.sh controls`, then `bash podread_smoothgap10k.sh names`.
