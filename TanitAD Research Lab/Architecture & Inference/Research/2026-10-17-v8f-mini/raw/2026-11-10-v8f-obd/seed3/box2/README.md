## Order of the chain
1. **Wait for STOPBAL.** `C:/Users/Admin/stopbal_state` (`OBD3_STOPBAL_STATE`, read only). Ended means: `DONE.txt` (first bytes: the STOPBAL done marker), or `STOP.txt` (the STOPBAL stop marker) whose reason is NOT a busy stop. A busy stop is a STOP line whose head (the text before ` :: `) ends in `rc=12`: STOPBAL never ran its stage and may be resumed, so the chain keeps waiting. A STOP with any other rc ends STOPBAL. Also required: the shared busy marker `C:/Users/Admin/box2_ship/BOX2_BUSY.txt` is absent. Polls: `OBD3_WAIT_POLLS` x `OBD3_WAIT_POLL_S` (default 1152 x 300 s = 96 h), then STOP with rc 12 (`predecessor-not-ended`). Then the chain claims the marker (noclobber) and releases it on every exit (moved to `box2_ship/busy_aside`).
2. **ship** = proof, with a fallback. The tree `D:\tanitad\obd\repo` and `D:\tanitad\obd\tree_manifest.json` belong to the OBD chain and are reused **read only** when proven. Step 1: the package's checker files go to `D:\tanitad\obd3\check` (own folder, each put re-hashed on box 2). Step 2: `obd3_check.py shipcheck`, ONE box-2 job: the commit equals the pinned code of record, `TIP_OBD.txt` equals it, every member of `tree_manifest.json` re-hashes, the trainer's needle strings are present. It writes only under `obd3\ship`. Proven: "skip ship", nothing built, nothing put into the tree (`$STATE/ship/<commit>/TREE_PROVEN.json`). Not proven (a changed member, a wrong TIP, no manifest, a missing needle): the fallback ships as the OBD chain did (tar and manifest from the commit by the pinned `obd_ship_tree.py`, every put re-hashed, the pinned `obd_refresh.py` overlays the SAME path, changed files copied aside first, rollback on failure, nothing deleted), and the shipcheck must then prove the tree or the stage refuses (rc 17).
3. **runs**, each: disk (>= 5 GB free on D:), GPU idle (no `python.exe`, and used memory below `OBD3_GPU_IDLE_MIB`, default **3500**: the PI's desktop apps hold about 2.4 GB of VRAM at 0 % util), the shipped checker files re-hashed against the package, argv pin (the line equals the frozen tokens), selfcheck gate (the OBD checker's BUILT-lever assertions, unchanged), per-run token (written only by the checker), training under the token, post check (summary steps, checkpoint seed and step, S, T and O moved, detach recorded), bank into `C:/Users/Admin/t2v8f_pulls/obd_<tag>/` (`ckpt_last.pt`, `summary.json`, `train_log.jsonl`, `RUN.done`, `gate_token.json`, `selfcheck.json`, `argv.txt`, `BANK_MANIFEST.json`, `BANK.done`; each file's sha256 equals box 2's own `certutil` hash, 3 attempts), then the cleanup job (the run's own `obd3\gate_out\<tag>` by literal path, logged as path and bytes in `CLEANUP.json`), which refuses without the `BANK_VERIFIED` marker the dev box puts after the bank is proven. Never a checkpoint.

## Failure behaviour
A gate, pin or token refusal of one run (stage rc 11) writes `ARM_REFUSED_<tag>.txt` and the chain goes on with the next run (the arms are independent, nothing has used the GPU); the chain then ends with STOP (rc 4), never DONE. Every other failure stops the chain with `STOP.txt` and the stage's reason: ship refused (rc 9), training or post check or transfer failed (5), disk low (6), a pulled copy whose sha256 differs from box 2's after 3 attempts (**rc 7**, nothing later starts, the data stays on box 2, no cleanup ran), package, commit or transport (8), box busy, python running or GPU not idle (12), timeout (11). A refusal at the start (commit, package, transport, STOPBAL wait) also writes `STOP.txt`. `STOP.txt` present blocks a plain rerun (rc 2).
