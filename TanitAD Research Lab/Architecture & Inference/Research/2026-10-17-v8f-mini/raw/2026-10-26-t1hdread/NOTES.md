# T1-HEADS reader: interpretations (PREREG_V8F_T1_HEADS @ae659d49), quoted line -> what the code does
Reader `t1hd_read.py` (sha256 in every JSON). Smoke = 24 windows, logged bucket, s0: development only, NOT outcome-bearing.

1. §1 "the logged row of the same clip, at or after t0, whose logged pose is nearest in world xy" -> candidates are rows t0..T-1 of the cache `pose_grid` (ClipStore); first argmin; OFF-ROUTE iff distance > 3.0 m. The cache pose_grid is float32, so the dump's float32 `s_pose`/`t_pose` match it exactly (tick-0 distance 0.0).
2. §1 "transformed from the logged frame at r'_S into the window-origin frame" -> `v8f_mini.transform_ckpt(rc[r'], pose_grid[r'], pose_grid[t0])`, float64. S side = the dump's `s_ckpt_w0`. A GT cell is scored only if on-route AND `rc_ok & has` at r'.
3. §2 "Per window, the mean over its scored ticks >= 1" -> nanmean over ticks 1, 2 of the scored ones; a window with none is NaN. Delta = mean over windows of (S - CTRV) on the same scored cells.
4. §2 "over the 141 episodes" -> all 2,399 windows stay in the arrays (ineligible ones NaN for S rows, -1 for F1 cells), so every resample draws from all 141 episodes. The returned `n_windows` is the eligible count, reported separately (`n`).
5. §2 CTRV "constant speed and yaw rate from the same pose; the curvature is the executed track's mean over the 1 s before that row" -> pose = `s_pose`; row r = j - age_s; kappa = mean over the 10 raw frames 2r-9..2r of `_pose_kappa0(omega, v)` (the programme's measured curvature: clamp(omega / max(v, 2 m/s), +-0.3)) from `ego_channels_native` on the EXECUTED track; frames before the clip start are not counted (min 6 frames, tick 0 of t0 = 3). Points on the constant-curvature arc at s = 30/50/80 m (speed does not enter: S's checkpoints are arc-indexed). STRAIGHT = (s, 0, 0) in S's frame. EXTRA sensitivity (never decisive, in `beside`): CTRV2 with the unclamped mean(omega) / max(mean(v), 0.5).
6. The executed track is REBUILT, not read: the tool's own `envelope` / `plan_to_world` / `hermite_frames` on the dumped plans from the logged native track. Extra check X1 (not in the PREREG): rebuilt `cl` and tick poses equal the dumps (0.0 on smoke and on the full first-launch file).
7. §2 T rows "(ticks >= 1) - (tick 0), on the same windows" -> W = windows with a scored tick-0 cell AND >= 1 scored cell at ticks 1, 2; the later side pools all their scored cells (1-2 per window), the tick-0 side one per window. Slot layout (2 per window, -1 = absent) lets `paired_episode_cluster_bootstrap` resample episodes; `_f1_reducer` drops the -1. Lat and lon have separate W.
8. `taniteval.ci` casts per-window arrays to float64 and numpy 2.5 rejects float indices inside `macro_f1` -> a thin int-cast wrapper around the UNCHANGED `_f1_reducer` (encoded cells are exact small integers).
9. §2 estimator values are the estimator's own rounded output (4 dp); the HOLDS / DEGRADES comparisons use them as returned. F = 0.0124 / 0.0073 (PREREG), 2F = 0.0248 / 0.0146.
10. §2 crawl stratum "own speed below the GT speed at r'_T - 2 m/s" -> dumped `v0` (measured speed at the tick) < pose_grid v at r'_T - 2.0. Majority baseline: the banked 0.3170 / 0.0707 beside the baseline of these cells. Beside rows are point estimates plus the same bootstrap; goal F1 uses the `tactical_metrics` recipe on cells.
11. K1 -> every row the read used is re-run as (a, a); delta, lo, hi must be exactly 0 (same function, same array: no transform, so "exactly" is safe).
12. K2 -> primary = the tool's own float32 arithmetic (TickRecorder._ckpt_frames) replayed: max 0.0 m. Beside: a float64 recompute (max 6.1e-5 m on the full first-launch file) against the 1e-4 tolerance and a COMPUTED float32 bound (3.3e-4 m) (R74).
13. K3 -> r' == t0 for S and T on all windows and distance <= 1e-6 (0.0 observed; the float32 half-ulp at the largest coordinate, 2.9e-5 m, is reported beside).
14. K4 -> logged-bucket runs, tick 0 only: S pos_err means over `rc_ok & has` windows and lat/lon macro-F1 vs the banked T0 fresh JSON (full precision) to 1e-3, plus n_valid / n cells equal; also reported vs the 3-4 dp values quoted in the PREREG. Per-window diagnostic vs the T0 npz (S ckpt, logits, argmax) is in the JSON; smoke: 24/24 argmax equal, S ckpt within 2.3e-5 m, logits within 3e-6.
15. K5 -> raw `s_ckpt` mirrored (y -> -y; psi -> -psi, which does not touch position) in S's own tick frame, then the same transform; paired (mirror - S) per arc, decisive configuration s0 (s1 reported beside). PASS = all three separated and delta > 0.
16. K6 -> a LEVEL comparison with the arm it degrades: F1(donor cells) - F1(self cells) on the same ticks >= 1 cells of the same W; donor = another-episode window, same tick index, nearest dumped `v0`, ties to the lowest window index. PASS = lat and lon both separated with delta < 0. (A delta-of-deltas cannot work: the donor arm's tick 0 is degraded too.)
17. K7 -> new float64 per-episode dumps cast to float32 vs the banked float32 `cl`, `fl`, `g`, bytewise; plus the manifest's sha256 over the float64 originals (all keys). Smoke: heads run vs the flags-OFF run, every key, native dtype.
18. R75: K5 / K6 effects were computed BEFORE the real run on the banked T0 fresh evals (tick 0, 2,399 windows, DEV): K5 mirror - S = +3.54 / +8.57 / +17.68 m (s0, all separated); K6 donor - self = -0.477 (lat) / -0.296 (lon) F1 (s0, separated). At 24 smoke windows neither separates (n too small), as expected.
19. If any control fails the JSON carries no outcome word: `OUTCOME` = REFUSED with the failed controls; the rows stay in `runs` and are not to be read as outcomes (R74).
20. Mutation checks of the reader's own controls (`MUTATION_CHECKS.json`): K1, K2, K3, K7 each go RED on a deliberate fault; a no-transform GT frame lifts the tick-2 GT-to-route median 1.1 -> 13 m; a flipped CTRV kappa sign moves the tick-0 CTRV error 1.50 -> 5.88 m. `test_outcomes.py` pins the section-5 boundaries.
