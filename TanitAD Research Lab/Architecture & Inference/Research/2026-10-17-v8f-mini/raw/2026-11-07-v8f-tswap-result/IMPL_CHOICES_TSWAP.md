## 2. How TSWAP substitutes them
At every replan of the model's rollout, `model.forward_infer` is wrapped on the instance (the planner calls `model.forward_infer(batch)`, `v8f_t1_eval_ri.py:634`):
1. TWIN: `twin_batch` of TOWN (copied verbatim from `../town/town_run.py:54-69`): the own batch with ONLY `SWAP_KEYS` (`p10f, base, pose_now, pose_t, pose_s, limit, limit_ok`) replaced by the LOGGED clip's values at the same time index j (rows <= j of `base_log`, through `V8FMiniWindows.item`, causal speed bucket recomputed by the tool's `causal_bucket`). `KEEP_KEYS` (`feats, frame_ok, nav, a_t, a_s`) are the same tensors. **The swap leaves TOWN's twin-batch rule unchanged.**
2. `out_twin = forward_infer(twin batch)`; its `out_twin["code"]` (= `_code_pred` of T on the logged state, :795) is the code O is given. Inside this twin call S also runs on the logged state and conditions only the twin's T (`ck_for_t`, :778); that is "T run on the LOGGED state" and is TOWN's twin as it was.
3. The OWN call is `forward_diag(batch, code_override = out_twin["code"])` (:861-870): the same `_forward` and post-map as `forward_infer`, with O reading the swapped code. S's output to O (`ck_for_o`), O's own inputs, the ages, the executor and the rollout state are the own call's. `forward_diag` with T's own code is the identity with `forward_infer` (its docstring; pinned here by controls 2 and 3).
4. The tick file (the tool's `TickRecorder`, unchanged) holds the PLAN O issued and the OWN T heads of the same call. A side file `tswap_<tag>.npz` holds, per row: window, episode, tick, j, ages, the 60-dim code O read and the 60-dim own code, the twin T outputs, the speeds, and whether the swapped input keys were equal.
Arms: `own` = the pinned tool (wrapper installs nothing). `tswap` = the above. `mutant` = steps 1-3 with `tb = dict(batch)` (twin := own, nothing swapped).
