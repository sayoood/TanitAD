## 2. Does an existing builder serve navtest?

UNVERIFIED which last-heading convention the 63 non-pick rows use (the pick row is repaired); the check tries the three possible conventions (`repaired`, `raw`, `pick_repaired_others_raw`) on the first token, LOCKS the one that matches, and requires it for every later token; a mixed table is no identity (tested). ## 4. Chunking, state, disk

* **Plan** (`NC.plan_chunks`): whole logs, sorted by name, packed greedily to <= 1,000 tokens; chunk tokens sorted; each chunk's `tokens_sha256` (= the bundle's `ctx.json` `tokens_sha256`) is its **data clause**. The plan is recomputed from the pinned token file, never trusted (`NC.verify_plan`), and its canonical sha256 is pinned by the sealed amendment. Real plan: 14 chunks, sizes <= 1,000 (test).
* **Per chunk** (`navpipe_chain.py` `run_chunk`): `NEW` -> **bundle** (GPU under the dev-box lock, via L1's launcher; disk guard first) -> **G-IDENT** -> `BUNDLED` -> **G-REACH** stamp for this bundle -> `GATED` -> **search** P2HEAD x 3 seeds (Step B's `run_search_cli`, UNCHANGED, with the chunk's data clause) -> `SEARCHED` -> **T1 score** (3 seams + the planted identity) -> `SCORED` -> **bank** (hash everything, manifest) -> `BANKED` -> **delete ctx** -> `DELETED`.
* **State file** `<work>/navpipe_state.json`: atomic (tmp + fsync + replace), status monotone (a skip or regress is refused), bound to the plan sha; resumable at any status. A stage whose output validates is skipped; an output that does not validate after its child ran is a STOP.
* **Disk peak per chunk (cap 1,000 tokens):** ctx 3.66 GiB + bundle 17 MB + search shards/merged 5 MB + seams/CSVs/harness output about 20 MB. After the chunk: ~40 MB kept (bundle.npz, merged search, scores, seams, CSVs, manifest), 14 chunks ~0.6 GB. exFAT 1 MiB clusters: ~25 files per chunk ~ 25 MiB allocated.
* **Order of work and a 1-chunk prefetch.** Sequential by default. `--prefetch 1` starts chunk k+1's GPU stage while chunk k searches (peak 2 ctx = 7.3 GiB; the guard counts both, and falls back to sequential when there is no room). Prefetch is tested on planted data only.
* **Merge**: per-chunk outputs are concatenated and **re-sorted to the global sorted-token order** (`NC.canonical_merge`): the analysis is order-sensitive in the last bits (`np.bincount` summation), and the sorted order is the order an unchunked bundle would have. **MEASURED (test on the real banked carve-B arrays, shuffled into 5 chunks): merged == unchunked byte for byte, and the analysis reproduces Step B's banked P2HEAD read exactly.**
