## 1. What happened (INHERITED from the MM's pod reading 2026-11-13; the crash itself MEASURED here on CPU)

* HB-s0 trained all 10,000 updates, ran its update-10000 evaluation, dumped the scores, saved `aux_drv.pt` (format `aux_drv/2`), `model_sft_A.pt`, `model_sft_B.pt` and `scorer_states_last.pt` (A/B scorer states, AUX state, HB LoRA + LoRA optimiser) at 12:41Z.
* The post-training "h48x" forward (the head's predictions on the frames of the excluded logs, written to `head_pred_h48x.npz`, which the frozen A5 reader REQUIRES: `manifest_a5_hb.json` file `hb_s0_b`) then raised `AttributeError: 'list' object has no attribute 'ctx'` (`scorer_finetune.py:3093 fwd(hb)` -> `:1993 HB.select_actx(hb, ...)` -> `aux_hb.py:171 hb.ctx(...)`). The trainer exited rc 1 without `ZZSFT_DONE`; the chain logged `ZZVDAC_CHAIN_FAIL HB-s0`; HB-SHUF was not run (stop rule 1 of the card's section 10).

## 2. The defect and its class (MEASURED: reproduced on CPU, `evidence/repro_unfixed_tip.txt`)

In `main()` the loop was `for hb in DataLoader(Subset(ds, h48x_idx), ...): fwd(hb)`. `hb` is ALSO `main()`'s HB trunk (`hb = HB.HBTrunk(model)`, built before the loop); `fwd()` is a closure that reads `hb` from `main()`'s scope **at call time**. The loop rebound `hb` to the batch list, so the first `fwd()` call executed `HB.select_actx(<list>, ...)`. The path had never run with a trunk: HA has none, and HC-s0 stopped at its launch gate.
**Class: "built, tested, and unreachable from its caller" (CLAUDE.md, fifth direction): a test that the mechanism WORKS is not evidence that it RUNS.** `test_vdac_hb.py` (133 checks on the unfixed tip, MEASURED) proved the copy trains and the head reads it, but ended its run before the only code that rebinds the name. Second face of the same class: a **closure variable shadowed by a loop variable in the same scope**, invisible to review because both uses are legitimate in isolation.

## 3. The fix and what proves it reaches the failing path

1. `refe/scorer_finetune.py`: the post-training block is now a closure `run_h48x()` with the loop variable renamed (`h48_batch`); the training path calls it. A whole-file scan of `main()` for every for/with target that a nested function reads at call time found **one** other overlap, `batch` (the training loop), whose only readers (`_flat_loss_grad`, `_g21_state`, `_vdac_run` and a lambda) are defined inside `if a.preflight:` and cannot run after the loop (MEASURED, `refe/test_vdac_hb_h48x.py` layer S). No other rebinding exists. The names `aux`, `model`, `optH`, `optL`, `cap` are not rebound by any loop.
2. `refe/test_vdac_hb_h48x.py` (new, 49 checks): drives the REAL `main()` with an HB trunk and the exclusion lever through the post-training forward and asserts `head_pred_h48x.npz` has one row per excluded frame. **RED on the unfixed tip** (`AttributeError ... 'ctx'`, `evidence/RED_on_unfixed_tip.txt`), **GREEN on the fixed file**; the shipped defect re-inserted into the fixed file turns it RED again; a static scan turns RED on the shipped loop and on a loop over `aux`.
3. `refe/vdac_a5_layer.py`: seven reversal entries so the trainer still peels back to blob `4df07e51...` (the a3cc6a77 trainer): MEASURED equal.

## 4. Completing HB-s0 WITHOUT retraining (the one execution change)

`scorer_finetune.py --h48x-only <run dir>` (new flag, default OFF; forbidden in any launch argv, every profile pins its argv exactly; `gate_checks` kind `control`). Run with HB-s0's own argv (`vdac_pod.sh ARM=HB-s0 MODE=h48x` builds it from the same source as `MODE=run`, token for token, plus the one flag): the process builds the model, head and HB copy exactly as the run did, loads `aux_drv.pt` (`HB.load_v2`, STRICT: key set, shapes, both optimiser states) and cross-checks `scorer_states_last.pt` (A scorer, AUX, HB LoRA: bit-equal to `aux_drv.pt`, else it REFUSES), refuses unless the saved update equals the argv's total (**10,000**), trains nothing, saves nothing but the outputs, and runs the **same** `run_h48x()` the training path runs, which uses the trainer's own `fwd()`. It writes `head_pred_h48x.npz` and `h48x_provenance.json` (sha256 and bytes of every loaded file, the update read back from each, the cross-check result, the frame count, the audit's excluded-frame count, sha256 of the output) into `--out`. It refuses to overwrite an existing `head_pred_h48x.npz`.
**Equivalence (MEASURED on CPU, tiny fixture, `test_vdac_hb_h48x.py` layer F):** a fixed-trainer HB run's `head_pred_h48x.npz` and the `--h48x-only` file from its saved state are **bit-identical** (log, token, step, logit, sdf_m). Mutations: a perturbed head and a perturbed HB LoRA each give a DIFFERENT file; a wrong saved update, a disagreeing states file, an existing output, a missing `aux_drv.pt`, a missing exclusion list are each REFUSED. **Not measured:** bit-identity on the pod's GPU/bf16 path (the training process never produced the file to compare); the head and copy weights are loaded exactly, so any difference could only be kernel nondeterminism, which the provenance would not hide (sha256 recorded).
