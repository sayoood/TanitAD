## Pre-data implementation deviations (declared; none changes the registered design)

Each was chosen on 2026-09-27 BEFORE any arm ran; the arms' own start times are in `chain_times.json`.

1. **Micro-batch 64 x accum 4** (the proxy trainer's default is 32 x 8). The pre-registration says only: "- Then **403 optimiser steps at effective batch 256**, which is one live epoch (103,168 sample passes)." Reason: the proxy is kernel-launch-latency bound while another session's job time-slices the GPU. The two splits see the identical sample stream (the sampler does not depend on the split) and the loss is split-invariant. PROOF (`refe/check_microbatch_invariance.py` -> `microbatch_invariance.json`): one real 256-sample batch, the real trainer, CPU fp32 -- max per-tensor relative gradient difference 32x8 vs 64x4 = 2.75e-06 (global relative L2 2.09e-07, bar 1e-05) with covered samples per micro-batch [4, 4, 5, 7, 8, 3, 4, 4] vs [8, 12, 11, 8] and cov_norm a GLOBAL constant (9.1809); the MUTATION (the scorer loss normalised per micro-batch) disagrees by 1.05 (goes RED: True).
2. **The scorer loss is computed on the covered samples only** -- the live masked formula (train.py: `(per x cand_m).sum() / (cov_norm x batch) x score_w`); an uncovered sample's all-zero set under mask 0 and the proposals' own scores never enter the on-policy loss. Equivalence: `refe/selftest_proxy_train.py` T1 (T1 covered-only loss == live masked formula (value): live 0.38566574 proxy 0.38566574; T1 ... every scorer gradient: max rel diff 9.44e-07 over 78 tensors; T1 MUTATION (denominator from the covered count) goes RED: mutated 0.77133149).
3. **The train cache stores the scorer's visual context only for frames carrying an on-policy set at any rank** (3530 of 10000 frames); the proxy reads it only for a labelled sample and refuses a labelled sample without it (selftest T3).
4. **Camera calibration: the live trainer's own table** (the pod's `train_grow/calib_table.json`, sha256 `772c00abfd5070f7...` = phase A's DONE digest); the locally built table did not cover every manifest log.
5. **Definitions fixed in `eval/proxy_eval.py` before the data**: position error = the winner's ADE over the 8 NAVSIM poses (L1 reported beside); a family 'separates adversely' when P_s's interval lies entirely on the worse side of W_s's (families6's own intervals); the best of 64 is not computed (64x the scoring cost).
6. **Harness labels prefixed `refe_m6_`** -- `score_navtest_refe.py` refuses labels that do not start with 'refe'.
