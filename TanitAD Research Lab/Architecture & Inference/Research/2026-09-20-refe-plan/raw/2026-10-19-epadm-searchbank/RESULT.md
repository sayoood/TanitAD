## 1. The adapter (`code/epadm_searchbank.py`, sha256 in the amendment draft)
Layout: one P2 bank (one set per token) plus **three candidate banks, one per search seed** (one set per (token, seed)); the gate's "any seed" rule then runs over the 3 search seeds exactly as R1's ran over 2 EP seeds, and the CLI takes them as `--cand-bank s0 --cand-bank s1 --cand-bank s2`. The search output of (token, seed k) lives in host slot k = the k-th lowest-aggregate non-pick slot of the fan; the label array is shared by the four banks (C-LABELS) and holds the output's own label there; a MOVED set carries `pred_logit_pick` at the pick slot and `pred_logit_out` at the host slot; an UNMOVED set is P2's set verbatim. The frozen gate (`ep_admission.py` sha256 `f0193372...`, checked at import) is not edited.
**Guards (each with a RED input and a mutation arm):** G1 keys / files aligned and bijective; G2 every output has a finite in-range label in the gate's head order, and the labeller's identity holds; G3 search config sha256 `299c6e63...`, checkpoint `ea31db22...`, head null, arm P2HEAD, seeds 20260927-29, token-list sha, bundle sha, labels-from-this-search-file; G4 the frozen pick rule reads the intended pick in EVERY set; G5 it reads P2's banked pick in the P2 bank.
**Carve-B identity (MEASURED, `raw/results/identity_carveB.json`; bank manifests p2 `7106ae14...`, s0 `621319ab...`, s1 `6344c5ee...`, s2 `dcc4977f...`):** 400 sets in each bank, 24 logs; mismatches 0 in P2 logits and labels and in each candidate's logits, labels and pick-rule read; changed picks per seed 108 / 104 / 106 = the search's moved counts (26.5 % of (token, seed)); `align_candidate` keys bijection, labels bit-equal and ckpt_step equal on all three; P2's rule pick equals the bundle pick on 400 / 400. Precision: the gate's loader casts to float32, so "bit for bit" is against the float32 cast of the sources (labels differ from their float64 source by at most 3.0e-8; `pred_logit_out` by exactly 0). A rebuild with the final adapter gives byte-identical units and manifests.
Carve-B facts worth knowing: `pred_logit_pick` (CPU re-score) differs from the GPU-banked bundle logit at the pick by up to 4.3e-3, which is why an unmoved set uses the bundle row (one token flips a 6.6e-6 near-tie otherwise).
