# E0d card -- refcv8 EMA-48,852 map rasters re-scored under the published thin-class protocol (MAP-3 / MAP-4 baselines) + E0f

**Question.** What do refcv8's banked map rasters read under a tolerance / best-threshold protocol (REFCV9_DESIGN 4.1 E0d, 5.2 MAP-3, MAP-4)?
**Instrument.** `e0d_score.py` (`extract` -> `read`), `test_e0d.py` (16 tests, 5 of 6 mutants killed, the 6th is an equivalent mutant), `raw/E0D_RESULT.json` (every cell), `raw/E0D_TABLE.md`. Zero training, CPU.
**Evidence class / tier.** MEASURED (ours). Perception instrument, map head vs SAM3 GT raster, label level (T0); not a planning or driving metric. ONE training seed; the head is deterministic given the frames.
**Estimator.** `taniteval/ci.py` episode-cluster bootstrap (B 2000, seed 0) -- *another draw of EPISODES* only. IoU = pooled counts; recall = pooled window mean over windows with >= 20 GT edge cells in the band.

## Protocol (declared in the script docstring before any statistic was read)
* **Data.** `F:/refcv9_mapsel/rast_s0` (planes psw pdrv pedge code gt, 1000 x 600, 10 cm), GT from the E0h cache (equal to the banked `gt` on 94 / 94 sampled windows). **DEV episodes only**: 70 episodes, 2,397 windows, of which 68 windows (2 episodes) carry no GT map => **2,329 scored windows / 68 episodes**. **HOLD was never opened** (the code refuses it).
* **FIT / SCORE.** Inside DEV, in the split file's rank order, even position = FIT (34 episodes with GT, 1,164 windows), odd = SCORE (34 episodes, 1,165 windows). Printed and asserted: **0 shared windows, 0 shared episodes**.
* **Thresholds** fitted on FIT counts only, per class **per band**: drivable `pdrv >= t` = best pooled IoU; drivable-boundary `pdrv >= t` = best pooled F@0.3 m; edge class `pedge >= t` = best pooled F@0.3 m. One global threshold per class and the swapped fold are beside.
* **Rows.** MAP-4 = drivable-union IoU ({1,2,3,4,6} vs `pdrv >= t`, valid = GT != 255, `nocls` counts as negative = perc8's convention). MAP-3a = lane tolerance-IoU (0.5 m): both planes rendered 0.5 m wide (square dilation 2 cells; a 1-px line becomes exactly 5 px), pooled pixel IoU. MAP-3b = recall of GT edge cells @0.3 m (3 cells) by the inner boundary of the drivable plane.
* **Bands.** 0-20 / 20-40 / 40-60 / 60-100 m (stored at 20 m so the perc8 five-band table can be checked).

## What this says for the bars (MM to pin)
* **MAP-3b: the design's reference 0.29 is the 0-60 m pooled number.** The like-for-like 0-20 m baseline is **0.377 (primary) / 0.402 (cross-fit)**; the bar 0.50 therefore asks +0.10 to +0.12, not +0.21. At 0-20 m the edge class with a fitted threshold already reads recall 0.42-0.45 at precision 0.33-0.36, above the boundary arm (0.40 at precision 0.24): the bar's "drivable-boundary" wording and the edge-class alternative should be decided.
* **MAP-3a: 1.5 x baseline = 0.348 (primary) or 0.392 (cross-fit)** on DEV under L-DIL. The lane definition changes the level 0.18 -> 0.35 (exact / L-DIL / tolerance-F k = 5); the ratio bar is only comparable within one definition, so pin one (primary here: L-DIL).
* **MAP-4:** the refcv8 reference is the table's first column; the bar is a paired not-worse test, run with this scorer on the same windows.

## Limits (stated, not fixed)
1. **No lane probability plane is banked** (planes are psw pdrv pedge code gt), so no lane threshold can be fitted: lane is scored at the declared operating point `code == 2`. Fitting one needs a re-roll that banks the lane probability (roll_s0 took 2,903 s on the dev box). refcv9's E1 rasters must bank it too, or the lane row stays at the decided point for both arms.
2. DEV only; HOLD unread. Thresholds for a later HOLD read are in the result JSON (`thresholds_fit_on_all_DEV_for_a_later_HOLD_read`: drivable 108 / 111 / 104 / 102, boundary 128 / 144 / 112 / 112, edge 8 / 6 / 5 / 4); HOLD itself is the MM's sealing step.
3. Half-DEV intervals are wide (34 episodes): lane 20-40 m and beyond cannot separate arms. One seed: a separated paired CI is necessary, not sufficient, for a lever claim (`H-ESTIM-SEED-1`).
4. The 60-100 m band is inside the raster (the head writes it) but scores 0.47 drivable and ~0 lane: it will not bar anything.
5. e-index -> clip id is the position in the sorted clip-id list of the battery `windows_s0.json`; verified by two independent checks (above), not by a stored map. No clip ids are in any file here.
6. Extraction stats (25 MB) live only at `E:/scratch_e0d_stats/stats_dev.npz` (sha256 `5c49f003...`); regenerable in ~5 min with `e0d_score.py extract`.

## E0f -- anchor drift and TemporalFuse weights (refcv8 EMA-48,852, `raw/E0F_RESULT.json`, `e0f_probe.py`)
