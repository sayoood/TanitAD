## 1. X4 — what was built, and the three inheritances it keeps

`stack/tanitad/models/v6.py` (spectrum seam only): `X4_LAYER_POLICY`, `layer_spectrum_policy`,
`x4_rank_verdict`, `LayerSpectrumMonitor`, `sigreg_trend_verdict`, `X4_RECOMMENDED_ACCUM`.
`stack/scripts/train_v6_staged.py`: `--x4-spectrum-layers` (default `tac,str`; `none` disables;
`op` is **refused** — the z_op monitor is the incumbent O6 block and cannot be moved under the new
flag), `x4_monitor_from_args`, `x4_trend_record`, the loop wiring, and the
`X4_spectrum_layers` **reported** probe in `STAGE_GATE_SPEC["S-W"]` + `run_stage_gate`.

Everything SIGREG_GATE_POWER.md landed is inherited, not re-invented:

1. **The ceiling is stamped unconditionally** — per-layer records are `spectrum_report` records, so
   `rank_ceiling`/`effective_rank_frac`/`ceiling_note` ride along. **Plus one new stamp this layer
   set forces:** `spectrum_report` marks `rank_admissible` against the O6/z_op constant (1024),
   which for a d=256 layer is a misreading trap wearing a field name. The monitor therefore
   overlays `rank_admissible_layer` (the layer's own `ceiling_min`) with an `admissibility_note`
   naming BOTH constants — neither number can be quoted as the other.
2. **Pooled accumulator per layer** — one `SpectrumAccumulator` ring per layer at the same
   `--spectrum-accum` (consecutive steps, same drift argument), cluster unit = **the step**
   (8 rows sharing 4 episodes — deliberately conservative over-grouping; the per-batch reading
   falls back to `block=1` and stamps that episode correlation is understated there).
3. **INCONCLUSIVE-capable verdicts** — `x4_rank_verdict` is `o6_rank_verdict` under the layer's
   policy: same three clauses, same interval-must-exclude-the-threshold firing rule, same
   phase-start reference discipline (taken at the first **layer**-admissible pooled reading; a
   resume re-baselines, stamped).

**And the C76 rule applied forward:** for a re-configured `d` that no simulation sized,
`layer_spectrum_policy` returns the RULE ceiling and **`floor=None` — clause 3 disabled and
stamped** (`"clause 3 DISABLED: no measured floor"`), because an invented threshold that can fail a
run is worse than no threshold.

### 1.1 The o6 loss-trend guard — wired where a loss exists, refused where none does

The brief's o6-trend finding (O6_ABLATION_AND_MASK_PROBE.md §4.1, MEASURED): on the same 48-row
batch a 2× collapse moves `effective_rank` **0.3 %** and the `o6_sigreg` loss **3.05×, 42.4 σ** —
the loss is the higher-power alarm exactly where the rank estimator is blind.

`sigreg_trend_verdict(baseline, current)`: robust (median/MAD) z of the current window against the
phase-start baseline (first 400 per-step values vs the rolling last 100), **fires on rises only**
(z ≥ 8; a falling o6 is the regulariser training), INCONCLUSIVE when under-sampled, and a
zero-variance baseline is floored at 2 % of |median| (stamped when it binds) so a degenerate series
cannot manufacture an infinite z. At the measured collapse level (0.4023 → 1.2283) it reads
**z ≈ 47, FAIL**; at healthy noise **z ≈ 0.1, PASS** (both pinned in tests).

⛔ **z_tac / z_str get NO trend guard, and the record says why:** no per-layer SIGReg loss exists —
`v6_loss_step` applies `stack.sigreg` to z_op only, i.e. X4's *"per-layer SIGReg"* half is
unimplemented in the trainer. The per-layer block emits
`{"applicable": false, "reason": "no per-layer SIGReg loss exists …"}` rather than a number
(the four-families rule: a missing metric is declared with its reason, never invented). Adding the
per-layer SIGReg **losses** would change training behaviour and belongs to a trainer-loss stream +
a PI decision, not to a monitoring change. The same scope stamp rides the op verdict: the trend
guard is a REPORTED monitor; gate promotion is the PI decision O6_ABLATION escalation 2 asked for.

## 2. P9 — probe-gradient saliency (`stack/scripts/probe_saliency_p9.py`)

For a FROZEN checkpoint and a chosen latent readout, S[t,h,w] = Σ_c |∂y/∂ pixels| per window,
aggregated per target. Targets:

* **speed / yaw** — the checkpoint's own `StepDisplacementReadout` on the ENCODED pair
  (z[−2], z[−1]) (trains from step 0 of S-W, so it is meaningful at the pause checkpoint);
* **ridge targets incl. `lead_gap`** — `probe_latent_state.py`'s P9 reuse dump (F-19's seam:
  *"the P9 probe-gradient saliency pass rebuilds nothing"*), **refused unless the dump's recorded
  checkpoint matches `--ckpt`** or `--accept-probe-family` states the operator verified it — a
  direction fit on another model's latents is a colourful, meaningless map;
* **lead-state is therefore computable only with an admissible dump**, and when it is not, the
  summary carries a `not_computable` record with the reason (never a silent drop).

**The rank_ceiling lesson, applied to saliency — the record carries its own vacuity:**

1. **Structural support is stamped AND verified.** `encode_window` encodes frames independently
   (no cross-frame attention), so a readout of z[j] can only reach frames[j] — zero energy outside
   the declared `support_frames` is a **graph fact**, and the record says so. The energy outside is
   *checked* to be exactly zero; nonzero flips `support_violation` (the guard is watched fire by
   mis-declaring a support on purpose in the tests). "Saliency concentrates on the last frames" is
   unwritable as a finding where it is true by construction.
2. **The FOV split names when it is vacuous.** The saliency map is in the image plane, so the
   `fov_mask` cell test (|azimuth| ≤ half-angle — MEASURED identical to `visibility_occ`,
   P4_FOV_PREDICATE.md, 0/7680 disagree) is applied to pixel **columns** through the encoder's own
   `CanonicalFrame` (cylindrical: linear; pinhole: atan; the default half-angle is asserted in the
   tests to BE `fov_mask`'s own signature default, not a copied 60). When the mask covers the
   frame's field, `in_fov_energy_share = 1.0` **by construction** and the record stamps
   `vacuous_by_construction: true`; with a narrower mask the split is informative (pinned at 0.5/0.5
   on a uniform map at 30° vs 120°).
3. **The P4 lesson rides the lead grouping.** For lead-state targets, windows are grouped by the
   lead's own in/out-of-field status at the agent centre — and the record states verbatim that
   **the out-of-FOV group is MEANINGFUL, not noise** (those beliefs can only be fed by earlier
   frames/context, which is exactly what their saliency shows) and must never be dropped or masked.
   Empty groups report n=0, never impute.
4. **Degenerate readouts are flagged, not normalised** — a zero-gradient map is reported
   `degenerate: true` with no PNG, instead of being scaled into fake uniformity.

**Runnable-at-a-checkpoint** (S-W→S-T pause): consumes the v6 trainer `ckpt.pt` or the fp16
snapshot (container unwrap mirrors `load_stage_init`'s 2026-08-16 fix), rebuilds the stack from the
checkpoint's own `v6_config` (defensive: unknown keys are dropped loudly, geometry mismatches
refuse), takes windows from `--windows-pt {"frames":[N,W,C,H,W'], lead_x_m?, lead_y_m?}`, writes
`p9_summary.json` + per-target `saliency_*.pt` + stdlib-PNG heatmaps. **GPU execution is not this
stream's**; the usage line for the pause is in the module docstring. CPU smoke: `--synthetic`
(tiny stack, quotable stamped NONE) — MEASURED here: 2 targets + 1 declared not-computable in
0.06 s, support exact-zero verified, artifacts written.

18 tests in `stack/tests/test_p9_saliency.py`, including the support guard watched FIRE, the
family/dim/zero-direction refusals watched fire, the vacuity stamp both ways, and the end-to-end
synthetic smoke.
