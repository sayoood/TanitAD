## ⭐ Cross-discipline transfer proposal of the day

**Source (non-AD):** *You Don't Need Strong Assumptions: Visual Representation
Learning via Temporal Differences* (TDV, arXiv 2606.15956) — generic video
self-supervised learning, no driving content. Its result: an image encoder plus
a **motion encoder** trained so that `z_t + m_t = z_{t+1}` matches
state-of-the-art dense-task recipes with no augmentation or masking — and
**fails when the motion encoder is removed**.

**Why it transfers:** our live anti-collapse thread has two open threads TDV
speaks to directly — H-RANK-8 (3-frame channel stacking makes Δz noise-like;
lag-1 Δz autocorrelation −0.075) and "what after k=1?". TDV says the temporal
difference must be given its OWN additive channel rather than folded into a
spatial encoder's input channels — which is precisely what stacking does.

**The TanitAD experiment it implies — H-RANK-17:** one v7-tiny arm (≈ 29 min
class; dev-box 4060 or Thor after the production run) adding an additive motion
latent `m_t = f(z_t, a_t)` with the L1 target `z_t + m_t ≈ z_{t+1}` to the
two-term champion, vs the champion itself, on the parity corpus; readouts
val-side participation, EM-vs-HOLD, decodability, with the constant control, the
pixel floor and printed n/d, via `/TanitAD_ValidateAIDesign`. Both outcomes are
committed in the field RESULT. Corollary arm: the same at n_stack=1 (settles
H-RANK-8 in the same session).

Runner-up transfers: (a) **Gigapixel self-play** (RL/games lineage, arXiv
2606.19641) → TanitSim's MVP as a box-world renderer over our real scenario
logs; (b) **PhyLatent's counterfactual-branch separation** (robotics/OGBench) →
a third gate on the v7-tiny ladder.

## Process hazards measured today (for the trap list — each cost a retry)

1. **The G: Drive mount serves recently-written files as unreadable
   (`Errno 22` / "Invalid request code") while they sync** — every `kb_add`
   rewrite of `library.json` poisons the *next* read for ~a minute; `git`
   itself flapped to "not a git repository" twice. ⇒ Verify every write by
   read-back; never chain dependent writes without re-reading.
2. **`python tools/kb_add.py …` can EXIT 0 with NO output and bank nothing**
   when the mount is mid-sync — an exit code is not evidence; the PDF's
   presence AND the index entry are.
3. **A mid-download connection reset leaves a correctly-named, truncated PDF
   (exactly 5 MiB, no `%%EOF`) that is NOT in the index** — and a `| tail`
   pipe masked the non-zero exit. A file that exists with wrong bytes is worse
   than a missing one. ⇒ `kb_add` should download to a temp path, check
   size/trailer, and rename atomically (hardening task flagged).
4. **`kb_add` has no index lock** — a concurrent add from another agent landed
   between my repair's write and its verify and clobbered it (measured:
   `1707.06347`). ⇒ lock-file around load-modify-write (same hardening task).
5. **The trigger brief and the register disagreed, and the register was right.**
   The brief quoted the two-term result as "participation ≈ 11"; the register
   read from disk (newer than the git-index copy I had read first) says
   `champ30k` val participation **6.499** — collapse *prevented* (plateau,
   H-RANK-11) but **still below the 8.56 floor** (H-RANK-13). It also already
   held H-RANK-11…15 — and H-RANK-16 landed while I was writing — so my
   proposed ID was renumbered twice, to **H-RANK-17**, chosen atomically at
