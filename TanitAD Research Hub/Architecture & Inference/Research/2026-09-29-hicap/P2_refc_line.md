**Exact wiring of the hierarchy hook (`refc_v3.py` `_hook`, Drive copy read directly; MEASURED by source reading, not by execution):** `pooled_seq` (the per-frame pooled conv features of the 3-frame window, from the core encoder) → `phi_tac` (causal TCN) → `z_tac_raw` [B, d_tac = 512]; **nav** (embedding + optional range/time args `(distance_norm, time_norm, args_valid)`) is added to `z_tac_raw` (`nav_to_tac`) and to `ctx` (`nav_to_str`) — E13, zero-init; the **five-channel ego block** is added to both (`ego_to_tac`, `ego_to_str`) — E11', zero-init, `keep` bit re-applied so a withheld block is exactly zeros; (`--max-speed-input` would add a third additive term — not on in refcv6; `--goal-point-inject` adds a predicted metric goal point read off `ctx` — not on in refcv6). Then `g_str = f(str_goal_head(ctx))` → `gstr_embed` → `gstr_film` → `z_tac = z_tac_raw·(1+γ)+β`; from `z_tac`: `lat_head_tac`/`lon_head_tac` (512→8 each), `tac_goal_head` → `g_delta` [B, 3 taus, 4 = (x, y, heading, speed)] (`g_tac = g_delta`; the echo-quotient `--echo-base` is OFF from v4b on), `tac_goal_tok_head` → `tac_goal_logits` [B, 22], and `tac_latent_proj(z_tac)` → `target_latent` (fed to the core decoder; detached unless `uplink_grad`). `bank_speed_pred = g_tac[:, 2 s slot, speed].detach()` is also emitted for the decoder's withheld-bank mode.

**Selection, exactly (`RefCV3Model.forward`, E9):** the core returns the emitted fan `out["anchor_traj"]` [B, N = 117, S = 8, 2], `out["sel_score"]` [B, N] and `out["reach_keep"]` (mask); `g2 = g_tac[:, 2 s slot, :2].detach()`; `sc = scorer(fan[:, :, SEAM_SLOT], z_tac.detach(), goal_point = g2)` (goal-distance score); `graft = goal_gate · sc["score"]` (zero-init gate); `blended = apply_seam_clamp(sel_score, graft, …)`; `rank = blended.masked_fill(~reach_keep, −inf)`; `idx = rank.argmax(1)`; `out["traj"] = fan[arange(B), idx]`, `out["sel_idx"]`, `out["wp_seq"]`, `out["sel_score_v3"] = blended`, `out["goal_dist"]`. Goals travel DOWN detached ("selection can never train the goal toward the fan"). The eval arm `os` reads `out["traj"]` ranked by `sel_score_v3`, never the training-time `a_star`.

### 4.2 What it would replace, and what it would add

* **Replaces** (only): the E9 block — `scorer` + `goal_gate` + `apply_seam_clamp` + the argmax over `sel_score_v3` — and, if it is meant to displace the emitted-fan confidence rather than blend with it, the `sel_score` ranking. Nothing upstream (encoder, decoder proposals, sampler, anchors) changes; goals still travel down detached.
* **Adds:** (i) a candidate-side embedding of each of the 117 emitted trajectories (with its factored lateral × longitudinal class from `refc_tactical.factor_from_kinematics`, its 2/4/6 s geometric end-points and, once arm C exists, its goal-token membership); (ii) a state-side embedding of `pooled` / `z_tac` / `g_str`; (iii) hierarchical positives/negatives across the three levels — the only new thing relative to what REF-C already has; (iv) a hierarchy-traversing eval (the STRATEGIC and TACTICAL "selected vs executed" families REF-C v3 reported `UNAVAILABLE, n = 0` for).
* **The selection headroom for this line is UNMEASURED.** The only oracle-in-fan numbers are for the older parity arms (REF-C-XL: oracle 0.1640 vs pick 0.4714, pick > 2× oracle on 45.4 % of windows; base 0.1914 / 0.4728) and refcv3 (`oracle_sel` 0.3668 vs `os` 0.4419). For refcv4b/refcv5-v2/refcv6 the emitted-fan oracle is not reported (refcv4b `oracle_sel` is an instrument defect), and "oracle − pick measures fan dispersion, not selector quality" (repo programme review). The first task of any selector arm is to measure oracle-in-emitted-fan on V0's fan.

## Implications for HiCAP (≤ 12)

1. **The reference is refcv6, but refcv6 has no result.** The nearest *measured* neighbour is refcv5-v2 (108,257,502 params; ADE 0–2 s 0.3079 [0.2795, 0.3390]; FAILS both bars; separably worse than refcv4b). Quote its numbers from registry §4.8, and say "refcv6 = pre-registered configuration" everywhere else.
2. **The floor is high and the noise is real.** `ha0_ext` 0.2874 and `ha` 0.2996 are not beaten: refcv4b (0.2975) ties both (`os − ha` −0.0021, `os − ha0_ext` +0.0101, neither separated) and refcv5-v2 (0.3079) is separated *worse* than `ha0_ext` (+0.0205 [+0.0043, +0.0390]). The programme's bar is ADE separated from BOTH floors **and** a 0.10 relative margin **and** ≥ 3× the same-panel replicate floor; a zero-lever replicate flags 5/9 metrics "worse". HiCAP arms need seed-1 replicates and the inference-seed floor from day one.
3. **The plug-in point is the E9 block of `RefCV3Model.forward`**: inputs `out["anchor_traj"]` [B,117,8,2], `sel_score`, `reach_keep`, `z_tac` (detached), `g_tac`, `g_str`; output `sel_score_v3` → argmax. Keep goals flowing down detached (winner's-curse firewall) and keep the `os` arm definition so the four-family harness scores it unchanged.
4. **Measure oracle-in-emitted-fan on V0 first.** For this line it is unmeasured (refcv4b `oracle_sel` invalid); older arms show pick > 2× oracle on ~45 % of windows but that is dispersion as much as selector quality, and re-scorers historically recovered ≤ 8.4 % (E-GOAL-4: 32–36 %, unreconciled). A selector cannot beat its fan: 117 emitted candidates, model-free oracle-in-vocab 0.1987 m.
5. **The headroom is longitudinal (88–92 %).** A better ranker on this fan is a longitudinal ranker; heading/curvature/yaw-rate barely move. The four families must be reported per family with the L1–L4 lateral and S1 (n > 0) non-regression clauses — `verdict_refcv6.py` already encodes them and returns `MISSING_DATA` on absence; reuse it.
6. **Token supervision is thin, and HiCAP's hierarchy sits on it.** Trained today: 14 action tokens (per-clip labels on 23.5 % of rows) and a geometric bearing goal. The 22-token goal head has never trained (arm C would be first); 15 strategic tokens have no refc path (corpus gap); 8 dead logits; 5/22 goal classes lack negatives; 10/22 are under the n ≥ 200 floor. Any level-wise contrastive score must carry masks, n and d.
7. **Inference inputs are stamped, and two are not yours to use.** Nav is ORACLE (ego-future, 4,719/4,719); `speed_max_input` is ego-future-derived and refused (31/4,572 sign readings, 0/147 eval); situation-classifier output may not enter any goal/token path; the t0 ego block is a legal initial state. State, per level, what the token is computed from.
8. **Traffic-light tokens are teacher signals with tiny eval support** (RED 8, GREEN 15, YELLOW 3 windows). Any traffic-light claim needs the ego-only comparison (BINDING) and is underpowered by construction on eval.
9. **One lever per arm, own arm, paired.** HiCAP must not ride with A/B/C/D; if it shares tokens with C it pairs against C or V0 explicitly. Resolve the known-negative `--sel-refined` inside BASE before reading a selector delta.
10. **Coordinate with REF-F.** The repo's DRAFT `PREREG_REFF_CONTRASTIVE_SELECTOR.md` (2026-09-29) already specifies a contrastive state–action selector over REF-C's fan on the parity lineage; HiCAP's novelty is the hierarchy — say so, and do not register the same experiment twice.
11. **Do not mix lineages or names.** Parity REF-C-base/XL (0.4728 / 0.4714, val-40, 881 windows — the basis of the repo's 2026-09-25 review) ≠ the B1/v7.2 refcv line (4,823 windows / 141 episodes); "v6" in the programme review is the flagship ladder, not refcv6; "refcv7" does not exist (nearest real "v7" objects: the v7.2 label release used by every refcv arm, and `PREREG_V7F.md`, the flagship v7 run).
12. **Labels: refcv6 is on v7.2, not v8.1.** Nothing REF-C has been run on the v8/v8.1 blob (`tac_SIT`, `nav_30s` [oracle], `speed_max_input`); a first HiCAP arm on v8.1 changes labels and method at once unless V0 is re-run on v8.1 too.
